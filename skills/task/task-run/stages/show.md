# Этап show: дифф и показ

Одна остановка перед коммитом: пользователь видит дифф в gitone и результат в браузере вместе. После замечаний шаг повторяется целиком, поэтому в коммит уходит ровно тот дифф, который он одобрил.

## Стенд

Задача без интерфейса (только бэкенд, конфиг, CI): вместо браузера запрос к стенду или автотесты worktree, причина в итог. Раздел «Стенд» в `rules.md` говорит, что стенд проекта видит, а что нет.

Стенд, порт и вкладка по [stand.md](../stand.md). У задачи с интерфейсом они обычно подняты ещё на implement.

## Сценарии

1. По одному на критерий приёмки, на L плюс граничные случаи и соседнее поведение. Сценарии с интерфейсом идут во вкладке из `stand.md`, пользователь видит клики. Скриншоты сохраняй вне worktree.
2. Сценарий не прошёл: чини, повтори затронутые автотесты и сценарий.

## gitone

Панель gitone открыта с начала работы, раздел «gitone» в [worktree.md](worktree.md). Её нет (закрыли, сессию перезапустили): открой по тому разделу.

Ветка уже с коммитом (круг исправлений после доставки), а gitone открыт без аргументов: он показывает только новые правки, для круга этого хватает. Полный дифф ветки дай в вопросе командой `gitone $(git merge-base origin/<база> HEAD)`, новые файлы (`git ls-files --others --exclude-standard`) перечисли: с аргументами gitone их не показывает.

## Вопрос

«Посмотри дифф в gitone и результат в браузере». В `preview`: сценарии с результатом, пути к скриншотам, diffstat, новые файлы.

- «Всё верно, доставлять» (рекомендую).
- «Есть замечания»: текстом через «Другое». Замечания в `findings` с `source: show`, затем implement, verify и этот шаг заново.
- «Остановить».

После одобрения запиши `reviewedDiff`: `git diff $(git merge-base origin/<база> HEAD) | shasum` вместе со списком новых файлов. Погаси стенд и закрой вкладку по `stand.md`, чтобы отпустить порт.
