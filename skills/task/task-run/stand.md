# Стенд и вкладка

Задача с интерфейсом (в `context.pages` есть страницы) показывает работу с первой правки интерфейса, а не только на шаге «Дифф и показ». Пользователь видит результат, пока его ещё дёшево поправить.

## Когда

- implement: перед первой правкой файла, который виден на этих страницах. Тесты и логика без экрана стенд не поднимают.
- show: стенд уже поднят. Не поднят (порт был занят, сессию перезапустили): подними сейчас.
- Гаси стенд и закрывай вкладку после одобрения на show, а также при стопе, `blocked` и остановке по просьбе: порт нужен другим задачам.

## Порт

Стенд из `project.json`, порт один на машину. Лок держит сам процесс сервера:

- запуск фоном из `<worktree>/<stand.cwd>`: `flock -n /tmp/task-run-port-<порт>.lock sh -c 'echo "<ID> <worktree>" > /tmp/task-run-port-<порт>.owner; exec <stand.start>'`;
- лок занят твоей задачей (`.owner`): это твой прошлый сервер, перезапусти;
- лок занят чужой задачей на implement: работай без стенда и напиши одну строку в чат: «Стенд занят задачей <ID>, вкладка откроется на показе». Не спрашивай: порт освободится сам, а вопрос посреди реализации её останавливает;
- лок занят чужой задачей на show: вопрос «Порт занят задачей <ID>», варианты «Подождать» и «Остановить». Чужой сервер не гаси;
- упал сервер, упал и лок: зависших локов не бывает.

## Вкладка

Вкладку открывает расширение Claude in Chrome (инструменты `mcp__claude-in-chrome__*`), чтобы пользователь видел и результат правок, и клики сценариев.

1. Своя новая вкладка на `http://localhost:<порт><страница>`, страница первая из `context.pages`. Чужие вкладки не трогай и не переиспользуй.
2. Dev-сервер сам обновляет страницу после правки. Перезагружай вручную, только если она не обновилась.
3. Сценарии show идут в этой же вкладке.
4. ID вкладки действует только в этой сессии. Продолжение в новой сессии открывает новую вкладку.

Расширения нет или оно не отвечает: открой адрес командой `open` и скажи об этом одной строкой. Сценарии тогда идут без него, пользователь видит их скриншоты в вопросе show.
