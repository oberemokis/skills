# Task fleet

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: herdr 0.8.0. Оркестратор раздаёт задачи сессиям: на каждую готовит ветку и worktree, открывает его в herdr отдельным workspace, запускает там Claude с `task-run` и следит за состоянием по файлу задачи. Пользователь видит каждую сессию в сайдбаре herdr и отвечает ей в её панели. Код оркестратор не пишет.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней.

## Когда применять

- пользователь вызвал `/oberemokis-skills:task-fleet` с ID задач или с промптом без задачи
- нужно поднять, перезапустить или закрыть сессии задач, запущенных раньше

## Когда НЕ применять

- одна задача в текущей сессии: это `task-run` напрямую
- поиск или ревью внутри своей сессии: встроенный субагент дешевле, ему не нужны ни worktree, ни панель
- сессия запущена не в herdr (`HERDR_ENV` не `1`): скажи об этом и остановись, чужим сеансом herdr снаружи не управляем

## Правила

### Вызов

`/oberemokis-skills:task-fleet <ID> [<ID> ...] [--level S|M|L]`, `/oberemokis-skills:task-fleet "<промпт>"` для работы без задачи, `--setup` для опросника. Скрипты и описания `task-run` лежат рядом: `<папка скилла>/../task-run/`.

### Проект

Запусти `node <папка скилла>/../task-run/scripts/resolve-project.mjs`. `missing`, `broken` или `--setup`: опросник по `../task-run/project.md`, задачи ждут его конца. Затем проверь подключения из `tracker.check` и `codeHost.check`. С данными в порядке вопросов нет.

Один запуск работает с одним проектом, тем, где запущен оркестратор. ID чужого формата (`taskId` не совпал) не бери, назови.

### Предел

Живых сессий задач на машине не больше трёх, считая чужие оркестраторы. Считай в момент запуска по `herdr agent list`: агенты Claude, у которых `cwd` внутри папки `worktree.dir` любого проекта. Проверку и запуск одной задачи выполняй одной командой под `flock ~/.local/state/task-run/fleet.lock`: два оркестратора иначе оба увидят свободное место.

Места нет: вопрос «Сверх предела» по каждой лишней задаче. «Отложить» (рекомендую): не запускать, сказать, как вызвать позже. «Ждать места»: запустить, когда закроется сессия. Сессия занимает место, пока жива, в любом состоянии, в том числе пока ждёт ответа продукта.

### Подготовка задачи

До worktree, потому что от этого зависит база:

1. Глаголы трекера из `rules.md`: «прочитать задачу» и «задача готова к работе и твоя». Не готова: задачу не берёшь, причину пишешь в чат.
2. База и способ доставки по разделу «База», с проверкой существующей ветки локально и на origin.
3. Worktree по шагам 1–7 раздела «Без `--fleet`» в `../task-run/stages/worktree.md`, без входа в него. Путь `<root>/<worktree.dir>/<ветка с - вместо />`. Git создаёт его с `--no-track`: `herdr worktree create` от `origin/<база>` ставит ветке upstream базы, и `git push` ушёл бы в неё.
4. `herdr worktree open --cwd <root> --path <путь> --label <ID> --no-focus`. ID панели в `.result.root_pane.pane_id`, workspace в `.result.workspace.workspace_id`, по номеру в сайдбаре их не угадывай. Ответ `already_open: true` и в панели живой агент: вторую сессию туда не запускай.

### Запуск

Имя агента это ветка в нижнем регистре с `-` вместо `/`, до 32 знаков: herdr принимает только `[a-z][a-z0-9_-]`.

Плагин загружен через `--plugin-dir`, если папка скилла лежит не в `~/.claude/plugins/cache/`. Тогда корень плагина это `<папка скилла>/../../..`, и каждая дочерняя сессия, в том числе перезапущенная, получает `-- --plugin-dir <корень>`: иначе у неё установленная версия без нужных скиллов.

1. `herdr agent start <имя> --kind claude --pane <панель> [-- --plugin-dir <корень>]`. Модель и режим разрешений не передавай: сессия берёт настройки пользователя.
2. Прочитай экран `herdr agent read <имя> --source visible`. herdr отвечает «готов» и тогда, когда Claude показывает вопрос о доверии папке. Вопрос есть: не отвечай за пользователя, назови ему workspace.
3. `herdr agent prompt <имя> "/oberemokis-skills:task-run <ID> --fleet --base <база> --branch <ветка> --worktree <путь> [--level X]"` без `--wait`.
4. Проверь, что сессия взялась за работу: `herdr agent wait <имя> --until working --timeout 15000`. Не взялась: промпт остался в поле ввода (так бывает сразу после диалога доверия), нажми `herdr agent send-keys <имя> enter` один раз и проверь снова.

### Надзор

На каждую сессию одна фоновая команда: `herdr agent wait <имя> --until working; herdr agent wait <имя>`. Первая половина не даёт ожиданию вернуться сразу у сессии, которая уже стоит. По уведомлению прочитай из `tasks/<ID>.json` только `stage` и поставь ожидание снова.

- `stage.waiting` сменился: одна строка в чат, «<ID> ждёт тебя: <waiting>, workspace <метка>». Уведомление herdr шлёт сама сессия, дублировать не надо.
- `close` закрыт: `herdr agent prompt <имя> "/exit"`. Workspace и worktree остаются, место освобождается.
- `idle` без смены этапа и без ожидания: сессия, видимо, получила ошибку API. Прочитай экран, при сетевой ошибке пошли ей «продолжай».

«Готово» определяется по файлу, а не по `idle` или `done` herdr: сессия, которая ждёт пайплайн фоновой командой, тоже стоит в `idle`.

Этап каждой задачи пользователь видит в панели «Задачи fleet» рядом с чатом. Её открывает модуль хуков плагина при запуске этого скилла и обновляет по тем же файлам задач. Закрытую панель возвращает `/fleet-panel`. Строку «ждёт тебя» в чат всё равно пиши: панель может быть закрыта или не помещаться по ширине.

### Пропала сессия

Агента с именем нет в `herdr agent list` или в панели оболочка. Прочитай `stage` из файла:

- `stopped` или `done`: так и задумано, ничего не делай;
- в панели снова Claude с `agent_session.value`, равным `session.claudeSession`: herdr сам поднял её после перезапуска. Верни имя `herdr agent rename <панель> <имя>`, новую сессию не запускай;
- иначе вопрос «Сессия <ID> завершилась на этапе <этап>». «Перезапустить с этапа»: новая сессия в той же панели с тем же промптом, `task-run` продолжит по файлу. «Оставить остановленной». Автоматически не перезапускай: Ctrl+C пользователя от падения не отличить.

У пропавшей сессии выполни глагол «приостановил» и скажи об этом в чат. Это единственное действие оркестратора в трекере: иначе флаг «в работе» копит время, пока его некому снять.

### Промпт без задачи

Вопрос «Нужны правки в коде?».

- «Да»: правки идут только через задачу, предложи завести её в трекере и вызвать `task-fleet` с её ID.
- «Нет, только чтение»: `git worktree add --detach <root>/<worktree.dir>/read-<имя> origin/<база>`, открыть в herdr, запустить с `-- --permission-mode plan --disallowedTools Edit Write NotebookEdit`, промпт передать как есть. Одного режима plan мало: его снимают, а основная папка может быть смонтирована в стенд. Такая сессия тоже занимает место.

### Ответы и уборка

- Ответ сессии читай коротко: `herdr agent read <имя> --source recent-unwrapped --lines 60`. Длинный не помещается: попроси сессию записать его в файл вне worktree и прочитай файл.
- Из JSON herdr бери только нужные поля, `context` из файлов задач в свой контекст не грузи.
- Уборка только по просьбе: `herdr worktree remove --workspace <id>`. Отказ `dirty_worktree_requires_force`: спроси, `--force` сам не добавляй. Ветка остаётся.
- Чужие workspace и панели не закрывай. `herdr worktree open` из репозитория без открытого workspace заводит ещё и workspace основной папки: закрывай его, только если он появился от твоей команды.

## Привязано к версии

herdr 0.8.0:

- ответы команд это JSON, кроме `agent read` и `pane read`;
- `worktree open` отвечает `root_pane`, `workspace`, `worktree` и `already_open`;
- `agent start` отвечает `idle` и `interactive_ready: true` поверх вопроса Claude о доверии папке;
- `agent prompt`, отправленный сразу после диалога доверия, может остаться в поле ввода, а состояние при этом `done`;
- `agent wait` без `--until` возвращается на первом устоявшемся `idle`, `done` или `blocked`;
- после перезапуска сервера herdr сам поднимает Claude в панелях (`resume_agents_on_restore`), но без аргументов запуска, имена агентов при этом пропадают;
- `worktree remove` закрывает workspace и не трогает ветку.

Claude Code 2.1.322, панель задач (`hooks/fleet-panel`): API модулей хуков в раннем доступе. Панель, открытая без просьбы человека (продолжение сессии), встаёт только от 144 колонок, уже вызов скилла или `/fleet-panel` открывают её при любой ширине.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| worktree до выбора базы | трекер и «База» до `git worktree add` | ветка от не той базы, а пересоздать её изнутри сессии нельзя |
| `herdr worktree create --base origin/<база>` | git с `--no-track`, потом `herdr worktree open` | upstream базы, `git push` уходит в неё |
| дочерняя сессия без `--plugin-dir` | флаг каждому запуску и перезапуску | у неё установленная версия плагина без нужных скиллов |
| встроенный субагент с изоляцией в worktree | `herdr agent start` в своём workspace | субагент живёт внутри оркестратора, в herdr его не видно |
| перезапуск пропавшей сессии без вопроса | вопрос, поднятую herdr сессию принять | пользователь мог остановить её сам, повтор доставки опасен |
| счётчик мест в файле | `herdr agent list` под `flock` | файл не знает о перезапусках и чужих оркестраторах |
| «готово» по `idle` | `stage` из файла задачи | `idle` и при ожидании пайплайна |
| `--force` при уборке | спросить, что с правками | незакоммиченная работа исчезнет |
