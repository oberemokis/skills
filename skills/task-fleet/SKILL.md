# Task fleet

> Точка входа: [core](../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: Herdr, ядро hc 0.1.20 и приложение 0.1.15. Оркестратор раздаёт задачи сессиям: на каждую готовит ветку и worktree, запускает агента с `task-run` в отдельном пространстве Herdr и следит за состоянием по файлу задачи. Какие агенты умеют вести задачу и чем они отличаются (команда, ID сессии, продолжение, вопрос о доверии), записано в таблице `AGENTS` скрипта `scripts/launch.mjs`, и больше нигде. Пользователь видит каждую сессию в сайдбаре Herdr, отвечает ей в её панели и смотрит дифф в панели Review. Код оркестратор не пишет.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней.

## Когда применять

- пользователь вызвал `/task-fleet` с ID задач или с промптом без задачи
- вызов без аргументов: после краха ядра, перезагрузки или нового терминала оркестратора поднять надзор над сессиями, запущенными раньше
- нужно перезапустить или закрыть сессии задач

## Когда НЕ применять

- одна задача в текущей сессии: это `task-run` напрямую
- поиск или ревью внутри своей сессии: встроенный субагент дешевле, ему не нужны ни worktree, ни пространство
- оркестратор не в терминале Herdr: `node <папка скилла>/../task-run/scripts/host.mjs` ответил не `hc`. Скажи «запусти оркестратор в терминале Herdr» и остановись. Старый herdr fleet поддерживал до версии плагина 2.x

## Правила

### Вызов

`/task-fleet <ID>[=минуты] [<ID>[=минуты] ...] [--level S|M|L] [--agent <вид>]`, `/task-fleet "<промпт>"` для работы без задачи, без аргументов для восстановления, `--setup` для опросника. Например, `/task-fleet PROJ-1=25 PROJ-2`: первая задача с ручной оценкой 25 минут, вторая с оценкой из трекера либо через оценщик. Отдели минуты от ID до проверки `taskId`; принимай только целые положительные минуты. Скрипты и описания `task-run` лежат рядом: `<папка скилла>/../task-run/`. Команды ядра описывает `hc --skill`, окна `herdr-app --skill`.

### Проект

Запусти `node <папка скилла>/../task-run/scripts/resolve-project.mjs`. `missing`, `broken` или `--setup`: опросник по `../task-run/project.md`, задачи ждут его конца. Затем проверь подключения из `tracker.check` и `codeHost.check`. С данными в порядке вопросов нет.

Один запуск работает с одним проектом, тем, где запущен оркестратор. ID чужого формата (`taskId` не совпал) не бери, назови.

`herdr-app status` не отвечает: окно Herdr закрыто. Сессии всё равно идут, их держит ядро, но вопросов и звонков пользователь не увидит. Скажи об этом одной строкой.

### Агент задачи

Флаг `--agent` вызова, иначе поле `agent` в `project.json`, иначе `claude`. Агента нет в таблице `AGENTS`: `launch.mjs` ответит кодом 2 со списком известных, назови его пользователю и не подменяй своим.

### Предел

Живых сессий задач на машине не больше трёх, считая чужие оркестраторы и всех агентов вместе. Живая сессия это терминал с агентом, если у терминала метка `task-fleet=1` или его `foreground.cwd` внутри `worktree.dir` любого проекта из `~/.local/state/task-run/*/project.json`. Агент в терминале: `status.app` из таблицы `AGENTS`, его программа на переднем плане или его процесс в дереве терминала от корня (`pid` в `hc get`). Одной группы переднего плана мало: сессии fleet идут под обёрткой, на переднем плане у них оболочка, а после Ctrl+Z агент из группы уходит вовсе. `cwd` из `hc ls` не годится: это папка запуска.

Места считает `scripts/launch.mjs` из «Запуска» под локом `~/.local/state/task-run/fleet.lock` и держит лок, пока в новом терминале не появится агент: иначе второй оркестратор его не посчитает.

Места нет (код 4): вопрос «Сверх предела» по каждой лишней задаче. «Отложить» (рекомендую): не запускать, сказать, как вызвать позже. «Ждать места»: запустить, когда закроется сессия. Сессия занимает место, пока жива, в любом состоянии, в том числе пока ждёт ответа продукта.

### Подготовка задачи

До worktree, потому что от этого зависит база:

1. Глаголы трекера из `rules.md`: «прочитать задачу» и «задача готова к работе и твоя». Не готова: задачу не берёшь, причину пишешь в чат.
2. База и способ доставки по разделу «База», с проверкой существующей ветки локально и на origin.
3. Worktree по шагам 1–8 раздела «Без `--fleet`» в `../task-run/stages/worktree.md`, без входа в него. Путь `<root>/<worktree.dir>/<ветка с - вместо />`. Шаг 6 записывает ветке базу, от неё панель Review считает дифф.
4. У задачи уже есть живая сессия Claude, запущенная руками вне fleet, если в `~/.claude/sessions/*.json` есть живой `pid` с `sessionId`, равным `session.agentSession` файла задачи (у старых файлов `session.claudeSession`), а `session.agentKind` равен `claude` или его нет. Тогда вторую не запускай, назови пространство. Терминал с меткой `task=<ID>` проверяет `launch.mjs` (код 5).

### Выбор входа для каждой задачи

- Пользователь дал время: обычный `task-run`, добавь к `--task-args` параметры `--minutes N --source user`. Иначе есть оценка в поле трекера по правилам проекта: то же, `--source tracker`; дни переводи по рабочему календарю трекера. Неизвестная единица или недоступное поле не равны пустой оценке: уточни.
- Поле пусто и ручной оценки нет: добавь к **launch.mjs** ключ `--estimate-first`. В той же сессии стартует [task-estimate](../task-estimate/SKILL.md), после плана он передаёт задачу `task-run`. `--level` не содержит минут и не пропускает оценщик. В трекер прогноз не записывай.
- Перезапуск: готовая `estimate` или задача уже дошла до implement и далее (в том числе старый формат) → `task-run` по состоянию. До плана без сохранённой оценки снова применяй выбор входа; при `--resume` оставь обычный «продолжай». Для промпта без задачи этот выбор не нужен.

### Запуск

Имя терминала это ветка в нижнем регистре с `-` вместо `/`, до 32 знаков `[a-z0-9_-]`. ID новой сессии выдаёт скрипт, если агент позволяет задать его заранее (Claude позволяет), и возвращает в `session`, поэтому перезапуск известен с первой секунды. Пространство `fleet-<имя>` и вкладку `fleet-<имя>-tab` назначает скрипт: незнакомый id Herdr заводит новым пространством с именем папки worktree.

Скиллы стоят ссылками в папках скиллов агентов, и каждая сессия, в том числе перезапущенная, видит их сама.

1. Одной командой, не фоном и с таймаутом инструмента не меньше 120 секунд (скрипт укладывается в `--budget`, 90 секунд):

   ```sh
   flock -w 20 -E 75 ~/.local/state/task-run/fleet.lock \
     node <папка скилла>/scripts/launch.mjs --name <имя> --cwd <worktree> --task <ID> --agent <вид> [--estimate-first] \
     --task-args '<ID> --fleet --base <база> --branch <ветка> --worktree <путь> [--level X] [--minutes N --source user|tracker]'
   ```

   Промпт `task-run` в синтаксисе агента собирает скрипт из `--task-args`: синтаксисы вызова скилла у агентов разные, и знать их оркестратору не нужно. Аргументы в одинарных кавычках. Скрипт проверяет терминал задачи и места, запускает `hc run --no-parent --keep` с метками `task-fleet=1`, `task`, `agent`, `agent-session`, `fleet-launch`, `herdr.space`, `herdr.tab`, `task-fleet.space` и `task-fleet.parent`, ждёт агента и возвращает окно на пространство пользователя, если запуск его увёл, даже при ошибке. Агент идёт внутри оболочки, обёртку `$SHELL -lc '…'` собирает скрипт: в своей команде встроенный код не пиши, хук lean-ctx его не пропустит.

   Модель и режим разрешений не передавай: сессия берёт настройки пользователя. Промпт идёт аргументом: текст через `hc send` приходит агенту в обёртке, и вызов скилла в ней не сработает. По `task-fleet.space` сайдбар Herdr (мод `over9k` раскладки workbench) ставит пространство задачи деревом под пространство оркестратора, по `task-fleet.parent` отличает сам оркестратор от других терминалов этого пространства: он над деревом, они под ним.
2. Ответ скрипта это JSON одной строкой, смысл по коду выхода:
   - 0, `started`: агент `agent` в терминале `address`, его сессия `session` (`null`, если ID агент выдаёт сам), пространство `space`; `trust: true` значит агент спрашивает, доверять ли папке worktree;
   - 4, `full`: мест нет, занятые в `live`;
   - 5, `exists`: у задачи уже есть терминал; `alive: false` значит агент из него вышел, дальше «Пропала сессия» (там `--replace`);
   - 6, `no-agent`: агент не появился за таймаут (`reason: timeout`) или вышел сразу (`reason: exited`: команды нет, сломан конфиг), его процесс скрипт погасил, оболочка осталась. Прочитай экран `hc read <адрес> --lines 40` и задай вопрос «<ID>: <агент> не запустился» с экраном в описании: «Запустить другим агентом» (`--replace --agent <другой>`) или «Отложить» (строка в чат, как убрать пространство: «Уборка»);
   - 75 от `flock`: лок держит кто-то другой, назови его по `lsof`;
   - 1 и 2: ошибка `hc` или вызова, текст в stderr.
3. `trust: true`: не отвечай за пользователя, строка в чат «<ID> ждёт тебя: доверить папку worktree, пространство <имя папки>». Пока он не ответил, статуса агента нет, и надзор увидит перемену, когда агент примет промпт. Иначе проверь, что сессия взялась: `hc wait <адрес> --timeout 60`, затем `status.state` в `hc get`. Не `working`: прочитай экран `hc read <адрес> --lines 0` и покажи пользователю.

### Надзор

Сессии не дети оркестратора, надзор идёт по меткам. Пока есть живые сессии, держи одну фоновую команду `node <папка скилла>/scripts/watch.mjs ~/.local/state/task-run/fleet-watch-$HC_TERMINAL_ID.json`. Она выходит только на перемене (статус, ход, агент в терминале и его остановка, конец терминала) и печатает изменившиеся сессии с `task`, `agent` (вид), `alive` (агент в терминале) и `stopped` (агент остановлен по Ctrl+Z). По выходу прочитай из `tasks/<ID>.json` только `stage` и запусти её снова. Код 3: ядро перезапускалось, пройди восстановление.

- Файла задачи ещё нет: сессия на этапе start, ничего не делай.
- Сессия на чтение (`task=read-…`): файла у неё не бывает. Конец хода: строка «<имя> ответила, пространство <имя>»; вопрос: «<имя> ждёт тебя»; агент пропал: строка «<имя> завершилась», перезапуск не предлагай, такую сессию дешевле поднять заново.
- `stage.waiting` сменился: одна строка в чат, «<ID> ждёт тебя: <waiting>, пространство <имя>». Звонит пользователю сам Herdr, дублировать не надо.
- `close` закрыт: `node <папка скилла>/scripts/stop.mjs <адрес>`. Скрипт находит процесс агента в дереве терминала и шлёт ему TERM и CONT, агент выходит, оболочка в пространстве остаётся, место освобождается. Код 1 и `alive`: агент не вышел за 10 секунд, покажи экран пользователю. `foreground.pid` не годится: это обёртка, она лидер сессии терминала, и с ней умрёт агент, а за ним панель и пространство. `hc kill` нельзя по той же причине.
- `stopped: true`: агента остановили по Ctrl+Z, сессия жива. Строка в чат «<ID> остановлена в терминале, пространство <имя>», перезапуск не предлагай.
- Статус `idle` или `error` без смены этапа и без ожидания: сессия, видимо, получила ошибку API. Прочитай экран, при сетевой ошибке `hc send <адрес> "продолжай"`.

«Готово» определяется по файлу, а не по `idle` или `done`: сессия, которая ждёт пайплайн фоновой командой, тоже стоит в `idle`.

Панели «Задачи fleet» нет: её модуль `fleet-panel` жил в плагине и удалён вместе с ним, команда `/fleet-panel` не работает. Этап задачи пользователь видит только по строкам в чате, поэтому строку «ждёт тебя» пиши всегда.

### Пропала сессия

Терминала с меткой `task=<ID>` нет, `state` у него `gone`, или агента в нём нет: `alive: false` в выводе надзора. Ни оболочка на переднем плане, ни пустой `status.app` ничего не значат: под обёрткой впереди всегда оболочка, а на вопросе о доверии папке статуса агента ещё нет. Остановленный агент (`stopped: true`) не пропал. Прочитай `stage` из файла:

- `stopped` или `done`: так и задумано, ничего не делай;
- иначе сразу глагол «приостановил» и строка в чат: иначе флаг «в работе» копит время, пока вопрос ждёт. Это единственное действие оркестратора в трекере. Затем вопрос «Сессия <ID> завершилась на этапе <этап>»: «Перезапустить с этапа», «Перезапустить другим агентом» (только если в таблице `AGENTS` их больше одного) или «Оставить остановленной». Автоматически не перезапускай: Ctrl+C пользователя от падения не отличить.

Перезапуск: `launch.mjs` по разделу «Запуск» с флагом `--replace`. Терминал задачи, в котором осталась оболочка (после краха ядра или выхода агента), скрипт закроет, а пространство с тем же id откроется заново. Терминал, где агент ещё жив, скрипт не тронет и ответит кодом 5. Набирать команду в оставшейся оболочке через `hc send` нельзя: из терминала агента текст приходит в обёртке `<hc from=…>`, и оболочка падает на разборе.

- тот же агент и его сессия на месте (у Claude файл `~/.claude/projects/*/<id>.jsonl`, `id` из `session.agentSession` или старого `session.claudeSession`): `--agent <вид> --session <id> --resume -- 'продолжай'`;
- другой агент или сессии нет: `--agent <вид> --task-args …` без `--session`, с прежними аргументами `task-run`. Новая сессия продолжит по файлу задачи, git и передаче handoff, если её оставила прежняя. Поле `plugin` в файле задачи осталось только у задач, начатых до отказа от плагина, версию правил по нему больше не сверяют.

### Восстановление

Вызов без аргументов и код 3 надзора: пройди по задачам проекта с `fleet: true`, у которых этап не `done` и не `stopped`. Живая сессия есть: под надзор. Нет: раздел «Пропала сессия».

Оркестратор, поднятый в новом терминале, видит сессии старого по меткам. Файл снимка надзора у него свой, поэтому первая же проверка покажет все живые сессии как перемену: прочитай их этапы и продолжай. У живой сессии `task-fleet.space` не своё пространство, `task-fleet.parent` не `$HC_TERMINAL_ID` или меток нет (запуск до 3.1.0): `hc label <адрес> task-fleet.space=<своё> task-fleet.parent=$HC_TERMINAL_ID`, иначе дерево в сайдбаре останется у старого оркестратора.

### Промпт без задачи

Вопрос «Нужны правки в коде?».

- «Да»: правки идут только через задачу, предложи завести её в трекере и вызвать `task-fleet` с её ID.
- «Нет, только чтение»: `git worktree add --detach <root>/<worktree.dir>/read-<имя> origin/<база>`, `launch.mjs` по разделу «Запуск» с `--task read-<имя>`, а после `--` вместо промпта `task-run` идут `--permission-mode plan --disallowedTools=Edit,Write,NotebookEdit,mcp__lean-ctx__ctx_patch,mcp__lean-ctx__ctx_call` и промпт пользователя как есть. Форма с `=` обязательна: без неё промпт уйдёт в список запрещённых инструментов. `ctx_patch` пишет в файлы мимо `Edit`, а `ctx_call` доходит до него по имени, поэтому запрещены оба. Одного режима plan мало: его снимают, а основная папка может быть смонтирована в стенд. Такая сессия тоже занимает место.

### Ответы и уборка

- Ответ сессии читай коротко: `hc read <адрес> --lines 60`. Пока сессия работает или ждёт вопроса, `hc read` отдаёт только экран. Длинный не помещается: попроси сессию записать его в файл вне worktree и прочитай файл.
- Из JSON `hc` бери только нужные поля, `context` из файлов задач в свой контекст не грузи.
- Уборка только по просьбе: `git status --porcelain` в worktree, грязно: спроси, `--force` сам не добавляй. Затем `git -C <root> worktree remove <путь>` и `herdr-app do space.close --id <herdr.space> --confirmed true` (окно закрыто: `hc kill <адрес>`). Ветка остаётся.
- Чужие пространства и терминалы не закрывай.

## Привязано к версии

Herdr, ядро hc 0.1.20 и приложение 0.1.15; остальное в `hc --skill`:

- `cwd` в `hc ls` это папка запуска, текущая лежит в `hc get` → `foreground.cwd`;
- `foreground` это группа процессов переднего плана: под обёрткой `$SHELL -lc '"$0" "$@"; …'` из `launch.mjs` там оболочка (`argv[0]` равен `/bin/zsh`), агент её дочерний процесс. Корень терминала, обёртка, лежит в `hc get` → `pid`, от него `launch.mjs` ищет агента вниз по дереву (`ps -o pid=,ppid=,stat=,args=`), в состоянии `T` агент остановлен. Агента видно в `hc get` → `status.app` (`claude-code`), без агента `status` равен `null`. У Claude, запущенного напрямую, `foreground.name` равен номеру версии, программа видна по `argv`;
- `hc ls` не отдаёт метки, их видно в `hc get`;
- явный `hc kill` и выход программы закрывают панель, а последняя панель закрывает пространство; `--keep` возвращает оболочку только после потери терминала (крах ядра, перезагрузка);
- терминал, запущенный агентом без `--no-parent`, Herdr показывает подагентом во вкладке родителя без своей панели, и он умирает вместе с родителем;
- незнакомый id в метке `herdr.space` создаёт пространство с именем папки; окно в фоне при таком запуске осталось на прежнем пространстве;
- `hc send` из терминала агента заворачивает текст в `<hc from=…>` для любого получателя, и оболочка такую строку не разберёт; без обёртки только с `notes = false` на всё ядро, а это выключит и отчёты детей агентам;
- на вопросе агента о доверии папке `status` равен `null`: агента видно только процессом в дереве терминала, а вопрос по экрану (у Claude `trust this folder`);
- первая строка `hc events` это снимок, дальше перемены, среди них частые смены заголовков.

lean-ctx 3.12.5: хук Bash и `ctx_shell` пропускают только команды из списка и не пропускают встроенный код (`sh -c`, `node -e`, `eval`). `hc`, `flock`, `herdr-app` и `claude` пользователь разрешает сам командой `lean-ctx allow <команда>`. Ответ `[BLOCKED]` на одну из них: остановись и назови команду, в обход через скрипт не иди.

Claude Code 2.1.325: промпт аргументом со слэш-командой запускает скилл и с `disable-model-invocation`; `--session-id` задаёт ID новой сессии, `--resume` поднимает её по ID; панель задач (`fleet-panel`, последняя версия под тегом `v3.1.0`) жила на API модулей хуков в раннем доступе.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| `hc run` без `--no-parent` | `--no-parent` и метки | подагент без панели и умирает с оркестратором |
| `hc kill` по закрытой задаче | `scripts/stop.mjs <адрес>` | панель и пространство закрываются вместе с ним |
| промпт `task-run` через `hc send` | `--task-args` у `launch.mjs` | обёртка ломает вызов скилла |
| промпт `task-run` своими руками в синтаксисе агента | `--task-args` | у агентов разный синтаксис вызова скилла, `$` в двойных кавычках съедает оболочка |
| считать агента по группе переднего плана | дерево терминала от `pid` | после Ctrl+Z агент уходит из группы, и живая сессия выглядит пропавшей |
| `hc wait --children` | `watch.mjs` по метке | новый оркестратор не видит детей старого |
| `--disallowedTools Edit Write …` перед промптом | `--disallowedTools=…` | промпт уходит в список инструментов |
| ответить на вопрос о доверии за пользователя | назвать пространство | папку доверяет человек |
| перезапуск пропавшей сессии без вопроса | вопрос, «приостановил» сразу | пользователь мог остановить её сам, повтор доставки опасен |
| «готово» по `idle` | `stage` из файла задачи | `idle` и при ожидании пайплайна |
| `hc run` своей командой с `$SHELL -lc '…'` | `scripts/launch.mjs` под `flock` | хук lean-ctx не пропускает встроенный код, а места без лока считаются наперегонки |
| `hc send` с командой `claude` в оставшуюся оболочку | `launch.mjs --replace` | из терминала агента текст приходит в обёртке `<hc>`, оболочка падает на разборе |
