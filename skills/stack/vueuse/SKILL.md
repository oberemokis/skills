# VueUse

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: `@vueuse/core` и `@vueuse/nuxt` 14.4.0, актуальные на момент написания. Требует Vue от 3.5.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

Скилл про соглашения, а не про перечень функций: их около трёхсот, и держать их список у себя бессмысленно, документация точнее и всегда под рукой.

## Когда применять

- нужна работа с браузерным API, у которой есть скучная обвязка: наблюдатели, слушатели, таймеры, медиазапросы, буфер обмена
- обвязка требует снятия слушателей при размонтировании, и это уже забывали сделать
- то же самое понадобилось во втором месте

Два конкретных примера из существующего кода, где библиотека оправдана. `useActiveSection` руками поднимает `IntersectionObserver`, хранит его в переменной и снимает в `onBeforeUnmount`: это `useIntersectionObserver`. Карусель фотографий руками считает координаты касаний и порог свайпа: это `useSwipe`.

## Когда НЕ применять

- задача решается десятью строками без слушателей и таймеров: своя функция читается лучше, чем зависимость
- функция нужна ровно один раз и обвязки в ней нет
- в Nuxt уже есть встроенный аналог: состояние это `useState`, куки это `useCookie`, загрузка данных это `useFetch`
- нужен один хелпер из библиотеки на весь проект: скопировать десять строк дешевле, чем добавить зависимость

Порог простой: библиотека окупается там, где есть подписка и её надо снимать. Где подписки нет, она чаще всего лишняя.

## Правила

### Аргумент принимай как MaybeRefOrGetter и разворачивай toValue

Так функции VueUse устроены сами, и свои композаблы стоит писать так же: тогда вызов работает и со значением, и с ref, и с геттером.

```ts
// хорошо
export function useUserPosts(userId: MaybeRefOrGetter<string>) {
  const url = computed(() => `/api/users/${toValue(userId)}/posts`)

  return useFetch(url)
}

// все три формы вызова работают
useUserPosts("42")
useUserPosts(userIdRef)
useUserPosts(() => props.userId)
```

```ts
// плохо: работает только со строкой, при смене id ничего не перезапросится
export function useUserPosts(userId: string) {
  return useFetch(`/api/users/${userId}/posts`)
}
```

### Вызывай в setup синхронно

Функции VueUse регистрируют хуки жизненного цикла, чтобы снять за собой слушатели. Вызов в условии, цикле, колбэке или после `await` эти хуки не регистрирует, и очистка не произойдёт.

```ts
// хорошо
const { x, y } = useMouse()
const isLarge = useMediaQuery("(min-width: 1024px)")
```

```ts
// плохо: слушатель повиснет
if (needsTracking) {
  const { x } = useMouse()
}
```

Это то же правило, что и для своих композаблов, оно описано в `vue`.

### Ручную обвязку заменяй целиком, а не наполовину

Смысл в том, чтобы отдать библиотеке и подписку, и отписку. Если оставить свой `onBeforeUnmount` рядом, получится две системы очистки и непонятно, какая сработала.

```ts
// хорошо
const target = ref<HTMLElement | null>(null)
useIntersectionObserver(target, ([entry]) => {
  if (entry?.isIntersecting) activeId.value = entry.target.id
})
```

```ts
// плохо: наблюдатель от библиотеки, а снятие своё
const { stop } = useIntersectionObserver(target, onIntersect)
onBeforeUnmount(() => stop())
```

### При серверном рендеринге проверяй, что функция вообще применима

Функции, которым нужен браузер, на сервере возвращают значение по умолчанию, а не падают. Это удобно, но означает, что первый рендер и клиент разойдутся.

```ts
// хорошо: значение читается после монтирования
const width = ref(0)
onMounted(() => (width.value = window.innerWidth))
```

```ts
// плохо: на сервере отдаст дефолт, при гидратации значение сменится
const { width } = useWindowSize()
// и разметка, зависящая от width, вызовет несовпадение
```

Разбор несовпадений гидратации лежит в `vue`, а хранилище браузера в Nuxt закрывается `useCookie`, который работает на обеих сторонах.

## Привязано к версии

Подписей конкретных функций здесь нет намеренно: их триста, и любая выборка из них устареет быстрее, чем понадобится.

Перед первым использованием проверь по установленной версии: имя функции, форму возвращаемого значения и наличие варианта, безопасного при серверном рендеринге. Правила выше про соглашения библиотеки, а не про конкретные подписи, и переживают мажоры лучше.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| зависимость ради одного хелпера без подписок | своя функция на десять строк | зависимость потом никто не убирает |
| VueUse там, где в Nuxt есть встроенное | `useState`, `useCookie`, `useFetch` | встроенное знает про сервер и гидратацию |
| аргумент композабла типом `string` | `MaybeRefOrGetter` и `toValue` | иначе вызов не переживёт смену значения |
| вызов внутри условия или после `await` | синхронно в setup | хуки очистки не зарегистрируются |
| своя отписка рядом с функцией библиотеки | отдать очистку библиотеке | две системы очистки, непонятно какая сработала |
| значение из браузерного API в первом рендере | читать после монтирования | сервер отдаст дефолт, при гидратации значение сменится |
| держать у себя список функций библиотеки | смотреть документацию | их около трёхсот, копия устареет за месяц |
