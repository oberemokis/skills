# Vite

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: Vite 8.2.2, актуальная на момент написания. Под капотом Rolldown вместо Rollup и oxc вместо esbuild, поэтому часть ключей конфига переименована. Тесты на Vitest лежат в `vitest`, сборка Nuxt настраивается через `nuxt.config.ts` и описана в `nuxt`.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

## Когда применять

- правишь `vite.config.ts`, настраиваешь сборку, алиасы, переменные окружения
- пишешь или подключаешь плагин
- разбираешься, почему значение из `.env` не подставилось

## Когда НЕ применять

- конфигурация тестов: это `vitest`, у него свой файл и свои ключи
- сборка приложения на Nuxt: конфиг живёт в `nuxt.config.ts`, Vite там внутри
- Environment API: конечному приложению он не нужен, это инструмент авторов фреймворков

## Правила

### Внутри конфига переменные окружения читаются вручную

Файлы `.env` разбираются после того, как конфиг уже разрешён, поэтому в самом `vite.config.ts` `process.env` пуст.

```ts
// хорошо
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), "")
  return { server: { proxy: { "/api": env.API_URL } } }
})
```

```ts
// плохо: undefined на этапе разрешения конфига
export default defineConfig({
  server: { proxy: { "/api": process.env.VITE_API_URL } },
})
```

### Строки в define оборачивай в JSON.stringify

Значение подставляется в код как есть, поэтому голая строка станет идентификатором и код перестанет собираться.

```ts
// хорошо
define: { __VERSION__: JSON.stringify("1.0.0") }
```

```ts
// плохо: в коде появится идентификатор 1.0.0
define: { __VERSION__: "1.0.0" }
```

Значения обязаны быть либо сериализуемыми в JSON, либо одиночным идентификатором.

### Воркер объявляется конструктором, а не суффиксом

```ts
// хорошо
const worker = new Worker(new URL("./worker.ts", import.meta.url), {
  type: "module",
})
```

```ts
// плохо: суффикс работает, но теряет типы и путь при переносе файла
import Worker from "./worker.ts?worker"
```

### Плагин только для сборки помечай явно

```ts
// хорошо
plugins: [{ ...somePlugin(), enforce: "post", apply: "build" }]
```

```ts
// плохо: плагин сборки поедет и в дев-сервер
plugins: [somePlugin()]
```

Без `apply` плагин поедет и в дев-сервер, где обычно ломает горячую замену. Это же нужно при подключении федерации модулей.

## Привязано к версии

Rolldown заменил Rollup, oxc заменил esbuild. Старые ключи Vite 8 не читает и об этом не сообщает, поэтому ошибка выглядит как «настройка не применилась».

| Было до 8 | Стало в 8 |
| --- | --- |
| `build.rollupOptions` | `build.rolldownOptions` |
| `esbuild: {}` | `oxc: {}` |
| `esbuild.jsxFactory`, `esbuild.jsxFragment` | `oxc.jsx: { runtime, pragma, pragmaFrag }` |

JSX поменял не только место, но и форму: вместо двух плоских ключей объект с `runtime`.

```ts
// хорошо
export default defineConfig({
  build: { rolldownOptions: { output: { manualChunks: {} } } },
  oxc: { jsx: { runtime: "classic", pragma: "h", pragmaFrag: "Fragment" } },
})
```

```ts
// плохо: оба ключа будут молча проигнорированы
export default defineConfig({
  build: { rollupOptions: { output: { manualChunks: {} } } },
  esbuild: { jsxFactory: "h", jsxFragment: "Fragment" },
})
```

Плагины при этом переносить не надо: Rolldown поддерживает API плагинов Rollup, и большинство работают без правок.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| `process.env.VITE_X` внутри конфига | `loadEnv(mode, process.cwd(), "")` | `.env` читается после разрешения конфига |
| строка в `define` без `JSON.stringify` | `JSON.stringify("...")` | подстановка дословная, строка станет идентификатором |
| `import.meta.env` в серверном коде Nitro | `process.env` или рантайм-конфиг | это переменные клиентской сборки |
| настройка Environment API в приложении | не трогать | инструмент для авторов фреймворков, приложению не нужен |
| `optimizeDeps` в расчёте на серверное окружение | настроить окружение явно | по умолчанию предбандлинг применяется только к `client` |
