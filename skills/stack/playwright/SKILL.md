# Playwright

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: `@playwright/test@1.62.1`, актуальная на момент написания. Монорепа на turbo и pnpm.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

Главное про этот скилл: начиная с 1.62 официальные скиллы поставляются внутри самого пакета Playwright. Правил здесь ровно столько, чтобы дожить до обновления и не наступить на версионные грабли.

## Когда применять

- пишешь или правишь браузерный тест
- тест падает непонятно, флакает, или надо разобрать трейс
- настраиваешь запуск в монорепе

## Когда НЕ применять

- сколько e2e держать, какие пути в них выносить, что не выносить: это `test`, там методология
- тесты компонентов и юниты: это `vitest`
- задачи и кеширование в монорепе: это `turbo`

## Правила

### Возьми официальные скиллы из пакета

С версии 1.62 Microsoft поставляет три скилла прямо в пакете: `playwright-cli` с разбором отладки, `playwright-trace` с анализом трейса из терминала и `playwright-component-testing` с новой моделью тестов компонентов. Написаны авторами, лежат под Apache-2.0 и обновляются вместе с инструментом.

```bash
# хорошо: сначала обновиться, потом поставить скиллы
pnpm add -D @playwright/test@latest
npx playwright init-skills --loop=claude
```

```bash
# плохо: до 1.62 команды init-skills нет, есть только init-agents
npx playwright init-skills
```

Команда молча не сработает на версии старше, поэтому порядок именно такой: обновиться, потом ставить. Если обновиться нельзя, правила ниже работают и без официальных скиллов.

### Отлаживай в терминале, а не глазами по видео

```bash
# хорошо
npx playwright test failing.spec.ts --debug=cli
PLAYWRIGHT_HTML_OPEN=never npx playwright test
npx playwright trace open trace.zip
```

```bash
# плохо: открывает интерактивный отчёт и ждёт человека
npx playwright test --reporter=html
```

`--debug=cli` останавливает тест в начале и печатает инструкции. Команду запускай в фоне и читай вывод, пока не появятся инструкции, потом не забудь остановить. `PLAYWRIGHT_HTML_OPEN=never` не даёт отчёту открыться сам. Разбор трейса командами `trace actions`, `trace errors`, `trace console` работает без браузера, начиная с 1.59.

### Локаторы по роли, а не по разметке

```ts
// хорошо
await page.getByRole("button", { name: "Оплатить" }).click()
await expect(page.getByRole("status")).toHaveText("900 ₽")
```

```ts
// плохо: сломается от любой правки разметки
await page.locator(".btn-primary > span").click()
await page.click("button")
```

Порядок предпочтения: роль, метка и подпись поля, текст, тестовый идентификатор, и только в крайнем случае селектор. Проверяя текст, следи, чтобы локатор сам не был построен по этому же тексту: иначе тест утверждает, что найденное найдено.

### Никогда не ждать время

```ts
// хорошо
await expect(page.getByRole("status")).toHaveText("Готово")
await expect
  .poll(() => api.getOrderStatus(orderId), { timeout: 10_000 })
  .toBe("paid")
```

```ts
// плохо
await page.waitForTimeout(5000)
await page.waitForLoadState("networkidle")
```

`networkidle` не использовать: он ждёт тишины в сети, которой в приложении с опросом не будет никогда. Разница между двумя способами ожидания в таймаутах: у `expect.poll` по умолчанию пять секунд и он слушается `expect.timeout` из конфига, у `toPass` таймаута нет вовсе и конфиг он игнорирует.

### Данные изолируй по воркеру, а не по тесту

Тесты в разных воркерах, трогающие одну базу или одного пользователя, сталкиваются, и падение выглядит случайным.

```ts
// хорошо: фикстура на воркер даёт свой набор данных
export const test = base.extend<{}, { tenant: string }>({
  tenant: [
    async ({}, use, workerInfo) => {
      await use(`tenant-${workerInfo.workerIndex}`)
    },
    { scope: "worker" },
  ],
})
```

```ts
// плохо: один и тот же пользователь на все воркеры
const USER = "test@example.com"
```

### В монорепе один пакет тестов на приложение

```json
// хорошо: turbo.json
{
  "tasks": {
    "e2e": {
      "dependsOn": ["^build"],
      "passThroughEnv": ["PLAYWRIGHT_*"],
      "outputs": ["playwright-report/**", "test-results/**"],
      "cache": false
    }
  }
}
```

```json
// плохо: e2e как корневой скрипт вне графа
{ "scripts": { "test:e2e": "playwright test" } }
```

`passThroughEnv` для `PLAYWRIGHT_*` нужен именно потому, что эти переменные не должны попадать в хеш: путь к браузерам меняется между машинами, а промах кеша из-за него бессмыслен. Пакет с тестами объявляет зависимость на пакет приложения через `workspace:*`, тогда `^build` соберёт приложение до прогона.

Если приложений несколько, `webServer` объявляется массивом, и тогда `baseURL` обязателен явно, даже когда в массиве одна запись. Учти, что `cwd` у `webServer` по умолчанию каталог файла конфигурации, а не корень репозитория.

## Привязано к версии

Ломающие изменения, которые уже произошли и о которых модель почти наверняка не знает.

| Версия | Что изменилось |
| --- | --- |
| 1.52 | в шаблонах `page.route` перестали работать `?` и `[]`, вместо них регулярные выражения |
| 1.57 | удалён `page.accessibility` |
| 1.58 | удалены селекторы `_react` и `_vue`, удалён суффикс `:light` |
| 1.59 | появились `--debug=cli` и `npx playwright trace` |
| 1.61 | появился `expect.soft.poll`, в трейсы и HAR попали запросы WebSocket |
| 1.62 | появилась команда `init-skills` с официальными скиллами, пакеты `@playwright/experimental-ct-*` объявлены устаревшими |
| 1.63 | устаревшие пакеты тестов компонентов удалены |

Отдельно про тесты компонентов: если вы на `@playwright/experimental-ct-vue`, потолок это 1.62.x. Новая модель работает через обычный `@playwright/test` с фикстурой `mount` и галереей историй, а старые пакеты больше не публикуются. Тесты компонентов Vue у вас всё равно идут через `vitest`, так что проще туда и не заходить.

## Антипаттерны

### Ожидания

```ts
// плохо
await page.waitForTimeout(3000)
await page.waitForLoadState("networkidle")
await page.click("button")
await page.fill("input", "текст")
```

```ts
// хорошо
await expect(page.getByRole("alert")).toBeVisible()
await page.getByRole("button", { name: "Отправить" }).click()
await page.getByLabel("Почта").fill("текст")
```

Отдельные методы `page.click` и `page.fill` работают, но не дают автоожидания локатора и не сообщают внятно, что именно не нашлось.

### Снапшоты доступности

```ts
// хорошо: пустая строка генерирует снапшот на месте
await expect(page.getByRole("main")).toMatchAriaSnapshot("")
```

Дальше файл обновляется флагом, и у него неочевидная семантика: без флага обновляются только отсутствующие снапшоты, с флагом без значения только изменившиеся. Полное обновление это `--update-snapshots all`.

### Прочее

| Не так | Так | Почему |
| --- | --- | --- |
| пропустить хук или добавить задержку, чтобы тест позеленел | найти причину | так закрепляется именно та ошибка, которую тест ловил |
| открыть приложение по адресу напрямую | идти через тест | в тесте есть подготовка, которой при прямом открытии не будет |
| прогонять сценарии параллельно, когда они делят сессию | последовательно | общая сессия делает порядок значимым |
| флакающий тест оставить в прогоне | выключить и завести задачу | команда привыкает перезапускать прогон вместо чтения ошибки |
| кешировать бинарники браузеров в CI | ставить заново | восстановление кеша занимает столько же, а зависимости системы всё равно не кешируются |
