# Vitest

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: Vitest 4.1.11, актуальная на момент написания, с `@vitest/coverage-v8`, монорепа на turbo. Четвёртая версия переименовала и удалила заметную часть ключей конфига, поэтому примеры из обучающих данных чаще всего описывают третью.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь. В этом скилле версионная часть больше поведенческой, так что при обновлении читать надо именно её.

## Когда применять

- правишь `vitest.config.ts`, настраиваешь проекты, покрытие, воркеры
- пишешь моки, подменяешь модули, время, случайность
- разбираешься, почему тест не находится, не изолируется или покрытие показывает не то

## Когда НЕ применять

- что покрывать тестами и на каком шве: это `test`, форма теста выводится из шва, а не из раннера
- браузерные сценарии целиком: это `playwright`
- сборка приложения: это `vite`, у него свой конфиг и свои ключи

## Правила

### Проекты объявляются в конфиге, отдельный файл больше не читается

`vitest.workspace.ts` в четвёртой версии не поддерживается. Молча: файл лежит, проекты не подхватываются.

```ts
// хорошо
export default defineConfig({
  test: {
    projects: [
      { test: { name: "unit", include: ["src/**/*.test.ts"] } },
      {
        test: {
          name: "integration",
          include: ["tests/integration/**/*.test.ts"],
          isolate: false,
          fileParallelism: false,
        },
      },
    ],
  },
})
```

```ts
// плохо: файл vitest.workspace.ts игнорируется
export default defineWorkspace(["packages/*"])
```

Пер-проектные `isolate` и `fileParallelism` это то, что нужно в монорепе: юниты бегут без изоляции и параллельно, интеграционные последовательно.

### Воркеры настраиваются верхним уровнем

`poolOptions` удалён целиком.

```ts
// хорошо
export default defineConfig({
  test: {
    maxWorkers: 4,
    // один воркер без изоляции задаётся так же, верхним уровнем:
    // maxWorkers: 1, isolate: false
  },
})
```

```ts
// плохо: ключ мёртвый
export default defineConfig({
  test: { poolOptions: { threads: { singleThread: true, maxThreads: 4 } } },
})
```

Пул по умолчанию `forks`, то есть дочерние процессы, а не потоки, хотя все статьи говорят про `threads`. `minWorkers` удалён, `memoryLimit` для vm стал `vmMemoryLimit`.

### Без явного include покрытие врёт

`coverage.all` и `coverage.extensions` удалены. По умолчанию в отчёт попадают только файлы, которые тест затронул, поэтому непокрытый модуль просто отсутствует и процент выглядит хорошим.

```ts
// хорошо
coverage: { include: ["src/**/*.{ts,vue}"] }
```

```ts
// плохо: в отчёте окажутся только затронутые файлы
coverage: { all: true, extensions: [".ts", ".vue"] }
```

### Ограничивай область поиска тестов

По умолчанию исключены только `node_modules` и `.git`, поэтому тесты находятся и в `dist`.

```ts
// хорошо
test: { dir: "src" }
// либо с сохранением дефолтов
test: { exclude: [...configDefaults.exclude, "e2e/**"] }
```

```ts
// плохо: перезатирает дефолты, node_modules снова в поиске
test: { exclude: ["e2e/**"] }
```

### restoreAllMocks не трогает автомоки

В четвёртой версии восстанавливаются только шпионы, созданные `vi.spyOn`. Автомоканный модуль остаётся автомоканным, и состояние течёт между тестами.

```ts
// хорошо: автомок сбрасывается явно
beforeEach(() => {
  vi.mocked(sendEmail).mockReset()
})
```

```ts
// плохо: автомок переживёт restore и утечёт в следующий тест
afterEach(() => {
  vi.restoreAllMocks()
})
```

У автомоканных объектов геттеры возвращают `undefined`, а методы не восстанавливаются вообще.

### Конструктор мокается функцией или классом

Стрелка не является конструктором, и подмена падает с «not a constructor».

```ts
// хорошо
vi.spyOn(mod, "Client").mockImplementation(function () {
  return { send: vi.fn() }
})
```

```ts
// плохо
vi.spyOn(mod, "Client").mockImplementation(() => ({ send: vi.fn() }))
```

### Теги объявляются заранее, флаг называется tagsFilter

Незаявленный тег бросает ошибку, потому что `strictTags` включён по умолчанию.

```ts
// хорошо: в конфиге
test: { tags: { db: {} } }
// в тесте
test("сохраняет заказ", { tags: ["db"] }, async () => {})
// в прогоне
// vitest --tagsFilter=db
```

```ts
// плохо: флага --tags не существует, тег без объявления бросит
// vitest --tags=db
```

Теги наследуются от родительского `describe`. Тег в JSDoc помечает весь файл, а не следующий тест. В `beforeAll` можно спросить `matchesTags(["db"])` и не поднимать базу, когда таких тестов в прогоне нет.

## Привязано к версии

Всё, что удалено или переименовано в четвёртой версии. Старые ключи не читаются, и в большинстве случаев ошибки не будет: настройка просто не применится.

| Было в третьей | Стало в четвёртой |
| --- | --- |
| файл `vitest.workspace.ts` | `test.projects` в конфиге |
| `poolOptions.threads.maxThreads` | `maxWorkers` верхним уровнем |
| `poolOptions.threads.singleThread` | `maxWorkers: 1, isolate: false` |
| `poolOptions.*.memoryLimit` | `vmMemoryLimit` |
| `minWorkers` | удалён |
| пул по умолчанию `threads` | пул по умолчанию `forks` |
| `coverage.all`, `coverage.extensions` | `coverage.include` |
| широкий `exclude` по умолчанию | только `node_modules` и `.git`, область задаётся `test.dir` |
| `deps.optimizer.web` | `deps.optimizer.client` |
| `deps.inline`, `deps.external` | внутри `server.deps` |
| `restoreAllMocks` сбрасывал и автомоки | касается только шпионов `vi.spyOn` |
| флаг `--tags` | `--tagsFilter` |
| отдельные каталоги отчётов и вложений | общий `.vitest`, одна строка в `.gitignore` |

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| стрелка в `mockImplementation` для конструктора | `function` или `class` | у стрелки нет `[[Construct]]`, это семантика JS, а не Vitest |
| покрытие без явного `include` | перечислить исходники | иначе в отчёт попадает только затронутое и процент выглядит лучше, чем есть |
| `exclude`, перезатирающий дефолты | развернуть `configDefaults.exclude` рядом | иначе в поиск возвращается `node_modules` |
| один прогон для юнитов и интеграционных | отдельные проекты с разной изоляцией | юниты выигрывают от параллельности, интеграционные от последовательности |
| тег, не объявленный в конфиге | сначала объявить | `strictTags` включён, прогон упадёт |
| тег в JSDoc в расчёте на один тест | помнить, что он помечает весь файл | интуиция из JSDoc здесь обманывает |
| `test` внутри `vite.config.ts` без ссылки на типы | `/// <reference types="vitest/config" />`, либо отдельный `vitest.config.ts` | иначе секция не типизирована |
| второстепенная проверка, обрывающая тест на первом падении | `expect.soft` | иначе остальные проверки не выполнятся и картина будет неполной |
| своя функция-проверка, вызываемая из тестов | обернуть в `vi.defineHelper` | без неё падение показывается внутри хелпера, а не в месте вызова |
