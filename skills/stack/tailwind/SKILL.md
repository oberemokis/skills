# Tailwind

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: `tailwindcss@4.3.3`, актуальная на момент написания, через плагин `@tailwindcss/vite`, подключённый в `nuxt.config.ts`. Файла `tailwind.config.js` нет и не должно быть: вся конфигурация живёт в CSS, точка входа `app/assets/css/main.css`.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

Четвёртая версия это переписанный движок, и почти всё, что модель знает про Tailwind, относится к третьей. Раздел «Привязано к версии» здесь не формальность, а главная часть скилла.

## Когда применять

- пишешь или правишь классы в разметке
- добавляешь цвет, шрифт, размер, точку останова
- нужен свой класс, которого нет в утилитах

## Когда НЕ применять

- реактивность и структура компонента: это `vue`
- конфигурация сборки: это `vite`
- как выглядит интерфейс, а не какими классами это записать: скилла на это нет, решай с пользователем

## Соглашения

Первые два пункта это соглашения, следующие три расхождения с ними, найденные в `app/assets/css/main.css` проекта `sagemis-web`.

- токены объявляются в `@theme`: сейчас это `--color-ink`, `--color-line`, `--font-tiempos`
- `@font-face` и глобальные правила для `html` и `body` лежат в том же файле после `@theme`
- `body` задаёт цвет литералом `#111111`, хотя токен `--color-ink` с тем же значением уже объявлен: должно быть `var(--color-ink)`
- `.snap-section` и `.reveal-init` объявлены обычным CSS, поэтому вариантов вроде `md:snap-section` у них нет. Если варианты нужны, это `@utility`
- медиазапрос `max-width: 860px` вписан числом, хотя точка останова могла быть токеном `--breakpoint-*` и заодно дала бы вариант в разметке

## Правила

### Токен в @theme, а не переменная в :root

Переменная в `@theme` делает две вещи сразу: объявляет нативную переменную CSS и порождает утилиты. Переменная в `:root` не порождает ничего.

```css
/* хорошо: появятся bg-ink, text-ink, border-ink */
@theme {
  --color-ink: #111111;
}
```

```css
/* плохо: переменная есть, утилит нет */
:root {
  --color-ink: #111111;
}
```

Соответствие такое: `--color-*` даёт `bg-*`, `text-*`, `border-*` и остальные цветовые утилиты, `--text-*` даёт размеры текста, `--font-*` даёт семейства, `--shadow-*` даёт тени, `--breakpoint-*` даёт варианты по ширине, `--animate-*` даёт анимации.

`:root` остаётся для значений, которые нужны только в рантайме и утилит не требуют.

Если значение токена ссылается на другую переменную, объявляй блок как `@theme inline`, иначе ссылка не раскроется в месте объявления.

### Объявил токен, используй токен

```css
/* хорошо */
body {
  color: var(--color-ink);
}
```

```css
/* плохо: значение продублировано, при правке токена разъедется */
body {
  color: #111111;
}
```

### Свой класс через @utility, если нужны варианты

Обычный класс в CSS работает, но остаётся без вариантов: ни `md:`, ни `hover:`, ни `dark:` к нему не применить.

```css
/* хорошо: md:snap-section и hover:snap-section заработают */
@utility snap-section {
  min-height: 100vh;
  scroll-snap-align: start;
}
```

```css
/* плохо, если варианты понадобятся */
.snap-section {
  min-height: 100vh;
  scroll-snap-align: start;
}
```

Обычный CSS уместен там, где класс всегда применяется как есть, без вариантов. Правило не в том, что `@utility` лучше, а в том, что выбор осознанный.

### Шкала отступов бесконечна, произвольные значения почти не нужны

Любое число компилируется через `calc(var(--spacing) * n)`, поэтому у большинства значений из третьей версии есть именованная форма.

```html
<!-- хорошо -->
<div class="w-150 min-w-100 p-6" />
```

```html
<!-- плохо -->
<div class="w-[600px] min-w-[400px] p-[24px]" />
```

Произвольное значение оправдано, когда число не кратно шкале или приходит извне.

### Переменная в утилите пишется круглыми скобками

```html
<!-- хорошо -->
<div class="bg-(--row-bg) text-(color:--fg)" />
```

```html
<!-- плохо: в четвёртой версии квадратные скобки требуют var() внутри -->
<div class="bg-[--row-bg]" />
```

Квадратные скобки остались для произвольных значений, и переменная в них пишется полностью: `bg-[var(--row-bg)]`. Подсказка типа нужна, когда значение неоднозначно: `text-(color:--fg)` против `text-(length:--size)`.

### Классы должны быть в исходниках буквально

Сканирование идёт по тексту файлов. Класс, собранный из частей, не найдётся, и стиль не появится.

```html
<!-- хорошо: полные имена, выбор через словарь -->
<div :class="variantClasses[variant]" />
```

```ts
const variantClasses = {
  solid: "bg-emerald-700 text-white",
  ghost: "bg-transparent text-emerald-700",
}
```

```html
<!-- плохо: такого текста в файле нет, класс не сгенерируется -->
<div :class="`bg-${color}-700`" />
```

Файл, который сканером не виден, тоже не даст классов. В Nuxt это касается генерируемого `.nuxt`: он под `.gitignore`, а сканер игнорируемое не читает. Если классы объявлены только там, добавляй путь через `@source`, и помни, что путь считается относительно CSS-файла, а не корня проекта.

### @apply в компоненте дороже, чем кажется

В `<style>` внутри компонента и в модулях CSS `@apply` не видит токенов темы, пока не указан `@reference` на входной файл. А `@reference` заставляет разбирать весь входной CSS на каждый такой блок.

```vue
<!-- хорошо: значение берётся переменной, разбирать нечего -->
<style scoped>
.card {
  background-color: var(--color-line);
}
</style>
```

```vue
<!-- плохо: либо не соберётся, либо соберётся дорого -->
<style scoped>
.card {
  @apply bg-line;
}
</style>
```

Проще всего вообще не писать `@apply` в компонентах: утилиты ставятся в разметку, а то, что в разметку не влезает, пишется обычным CSS через переменные темы.

## Привязано к версии

Всё ниже относится к переходу с третьей версии на четвёртую. Модель почти наверняка предложит левый столбец.

Директивы и конфигурация:

| Было в 3 | Стало в 4 |
| --- | --- |
| `@tailwind base/components/utilities` | `@import "tailwindcss"` |
| `tailwind.config.js` подхватывался сам | конфигурации в JS нет, токены в `@theme` |
| `@layer utilities { .x {} }` | `@utility x {}` |
| `content: [...]` | автоопределение плюс `@source` |
| `safelist: [...]` | `@source inline("…")` |
| `theme(colors.red.500)` | `var(--color-red-500)` |
| `darkMode: "class"` | `@custom-variant dark (&:where(.dark, .dark *))` |
| PostCSS-плагин `tailwindcss` | `@tailwindcss/vite` или `@tailwindcss/postcss` |
| `@apply` в компоненте работал сам | нужен `@reference` |

Переименованные утилиты. Шкала сдвинулась на шаг, поэтому старое имя даёт другой размер, а не ошибку:

| Было в 3 | Стало в 4 |
| --- | --- |
| `shadow` | `shadow-sm` |
| `shadow-sm` | `shadow-xs` |
| `rounded` | `rounded-sm` |
| `rounded-sm` | `rounded-xs` |
| `blur` | `blur-sm` |
| `blur-sm` | `blur-xs` |
| `ring` | `ring-3` |
| `outline-none` | `outline-hidden` |

Удалённые утилиты:

| Было в 3 | Стало в 4 |
| --- | --- |
| `bg-opacity-50`, `text-opacity-*` и прочие `*-opacity-*` | модификатор через слеш: `bg-black/50` |
| `flex-shrink-*`, `flex-grow-*` | `shrink-*`, `grow-*` |
| `overflow-ellipsis` | `text-ellipsis` |

Изменённые значения по умолчанию, каждое ломает вид молча:

- цвет границы был `gray-200`, стал `currentColor`
- обводка была `3px` цветом `blue-500`, стала `1px` цветом `currentColor`
- цвет подсказки в поле был `gray-400`, стал цветом текста с половинной прозрачностью
- курсор у кнопок был `pointer`, стал `default`
- `hover:` теперь под `@media (hover: hover)` и на сенсорных экранах не срабатывает
- модификатор важности переехал в конец: было `!flex`, стало `flex!`
- варианты складываются слева направо: было `first:*:pt-0`, стало `*:first:pt-0`
- Sass, Less и Stylus не поддерживаются, включая `<style lang="scss">` в компоненте

## Антипаттерны

### Значения вместо токенов

```css
/* плохо: тема объявлена, но не используется */
@theme {
  --color-ink: #111111;
}

body {
  color: #111111;
}

.note {
  border: 1px solid #ececec;
}
```

```css
/* хорошо */
body {
  color: var(--color-ink);
}

.note {
  border: 1px solid var(--color-line);
}
```

### Классы, которых не найдёт сканер

```html
<!-- плохо -->
<div :class="`text-${size}`" />
<div :class="'bg-' + color + '-500'" />
<div class="grid-cols-[1fr,2fr]" />
```

```html
<!-- хорошо -->
<div :class="sizeClasses[size]" />
<div :class="colorClasses[color]" />
<div class="grid-cols-[1fr_2fr]" />
```

Последняя пара про отдельную ловушку: запятые в произвольных значениях заменены подчёркиваниями.

### Прочее

| Не так | Так | Почему |
| --- | --- | --- |
| `tailwind.config.js` | `@theme` в CSS | в четвёртой версии конфигурация в JS не подхватывается |
| `@tailwind base` | `@import "tailwindcss"` | директивы заменены импортом |
| `bg-[--var]` | `bg-(--var)` | квадратные скобки теперь требуют `var()` внутри |
| `outline outline-2` | `outline-2` | утилита сама ставит стиль обводки |
| `transition-[opacity,transform]` | `transition-[opacity,scale]` | преобразования разложены на отдельные свойства |
| `transform-none` для сброса | `scale-none`, `rotate-none`, `translate-none` | сброс тоже по отдельным свойствам |
| `@theme` внутри селектора или медиазапроса | только верхний уровень | вложенный блок не работает |
| точка останова числом в медиазапросе | токен `--breakpoint-*` | заодно появится вариант в разметке |
