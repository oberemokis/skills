# Несовпадения гидратации

Читается из [SKILL.md](./SKILL.md) и из скилла `nuxt` при работе с серверным рендерингом.

Гидратация ломается, когда разметка с сервера не совпадает с той, что клиент построил бы сам. Vue сообщает об этом предупреждением, дальше выбрасывает серверную разметку и перерисовывает поддерево целиком, то есть вы теряете и производительность, и иногда состояние.

## Текст ошибки указывает на причину

| Что в предупреждении | Где искать |
| --- | --- |
| text content mismatch | недетерминированное значение в тексте: дата, случайность, локаль |
| children mismatch | невалидная вложенность тегов, браузер перестроил дерево |
| attribute mismatch | атрибут вычисляется по-разному на сервере и клиенте |
| node mismatch | отрендерены разные элементы, обычно из-за условия по `window` |

## Четыре причины, других почти не бывает

### Недетерминированное значение в рендере

```vue
<!-- плохо -->
<template>
  <div :id="`field-${Math.random()}`">
    {{ new Date().toLocaleTimeString() }}
  </div>
</template>
```

```vue
<!-- хорошо: значение приходит после монтирования -->
<script setup lang="ts">
const currentTime = ref("")

onMounted(() => {
  currentTime.value = new Date().toLocaleTimeString()
})
</script>

<template>
  <div :id="fieldId">{{ currentTime }}</div>
</template>
```

Идентификаторы генерируй детерминированно: из данных, из индекса, из `useId`. Если случайность нужна по смыслу, посей её одинаково на обеих сторонах.

### Невалидная вложенность тегов

Браузер молча перестраивает дерево, и клиентская структура перестаёт совпадать с серверной. Частые случаи: блочный элемент внутри `p`, `div` внутри `p`, ссылка внутри ссылки, `tr` без `tbody`.

```vue
<!-- плохо: браузер вынесет div из p -->
<template>
  <p>
    Описание
    <div>{{ details }}</div>
  </p>
</template>
```

```vue
<!-- хорошо -->
<template>
  <div>
    <p>Описание</p>
    <div>{{ details }}</div>
  </div>
</template>
```

### Часовой пояс и локаль

Сервер и браузер почти всегда в разных поясах, поэтому любое форматирование даты на сервере даст другую строку.

```ts
// хорошо: на сервере отдаём машинный формат, форматируем на клиенте
const isoDate = order.createdAt
const humanDate = ref("")

onMounted(() => {
  humanDate.value = new Intl.DateTimeFormat("ru").format(new Date(isoDate))
})
```

```ts
// плохо: строка разойдётся между сервером и клиентом
const humanDate = new Intl.DateTimeFormat("ru").format(new Date(order.createdAt))
```

### Условие по window или document

```ts
// хорошо: на сервере значение по умолчанию, реальное после монтирования
const isWide = ref(false)

onMounted(() => {
  isWide.value = window.innerWidth > 1024
})
```

```ts
// плохо: на сервере window нет, ветка выберется другая
const isWide = window.innerWidth > 1024
```

## Когда расхождение допустимо

Иногда несовпадение неизбежно и осмысленно: время последнего визита, случайный порядок баннеров, значение из локального хранилища. Тогда его надо разрешить точечно, а не глушить предупреждения целиком.

```vue
<!-- хорошо: разрешено ровно текстовое расхождение и ровно здесь -->
<template>
  <span data-allow-mismatch="text">{{ lastVisitedAt }}</span>
</template>
```

Допустимые значения: `text`, `children`, `class`, `style`, `attribute`. Без значения атрибут разрешает любое расхождение на этом элементе, и такой вариант стоит применять последним.

## Отладка

В разработке подробности расхождения видны, в продакшен-сборке по умолчанию нет. Включается флагом сборки:

```ts
// vite.config.ts или nuxt.config.ts
define: {
  __VUE_PROD_HYDRATION_MISMATCH_DETAILS__: "true",
}
```

Держать его включённым в продакшене не надо: он тянет в сборку код сравнения деревьев.

Порядок разбора такой. Прочитать тип расхождения из предупреждения, найти по таблице выше класс причины, посмотреть на конкретный элемент из сообщения. Если элемент выглядит невинно, смотри его родителя: невалидная вложенность проявляется на потомке, а вызвана уровнем выше.
