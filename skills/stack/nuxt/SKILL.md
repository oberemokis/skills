# Nuxt

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: Nuxt 4.5.2, актуальная на момент написания, внутри Vue 3.5, vue-router 5, Nitro 2. Четвёртая версия переехала на `app/` как корень исходников и поменяла смысл алиаса `~`, поэтому примеры из обучающих данных чаще всего описывают третью.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

## Когда применять

- страницы, роутинг, layouts, загрузка данных, `nuxt.config.ts`
- серверный рендеринг: гидратация, контекст, состояние между запросами
- раскладка файлов и автоимпорты

## Когда НЕ применять

- код внутри компонента, реактивность, свои композаблы: это `vue`
- серверные обработчики и middleware: это `nitro`
- классы в разметке: это `tailwind`

## Правила

### Корень исходников это app, а ~ указывает на него

```
app/          компоненты, страницы, композаблы, плагины
server/       обработчики Nitro, в корне репозитория
shared/       код для обеих сторон, в корне
public/  modules/  layers/  nuxt.config.ts
```

Алиасы: `~` и `@` ведут в `app/`, `~~` и `@@` в корень репозитория, плюс `#shared` и `#server`.

```ts
// хорошо
import { formatPrice } from "~/utils/format"
import type { Order } from "#shared/types/order"
```

```ts
// плохо: в четвёртой версии это уже не корень
import { handler } from "~/server/api/orders"
```

Смысл `~` изменился между мажорами, поэтому импорты ломаются молча: путь существует, но ведёт не туда.

### Состояние на уровне модуля течёт между запросами

Объявленный в композабле `ref` вне функции на сервере общий для всех запросов. Данные одного пользователя увидит другой.

```ts
// хорошо
export function useCart() {
  const items = useState<Item[]>("cart", () => [])
  return { items }
}
```

```ts
// плохо: один массив на весь процесс
const items = ref<Item[]>([])
export function useCart() {
  return { items }
}
```

Локально это работает и выглядит правильно, потому что процесс обслуживает вас одного.

### Композаблы Nuxt вызываются до первого await

После `await` в обычной функции контекст Nuxt потерян, и вызов падает с «Nuxt instance unavailable».

```ts
// хорошо
const route = useRoute()
const config = useRuntimeConfig()
const data = await loadSomething(route.params.id)
```

```ts
// плохо
const data = await loadSomething()
const route = useRoute()
```

### Данные грузятся useFetch, а не голым $fetch

`$fetch` в setup выполнится дважды: один раз на сервере, второй при гидратации на клиенте.

```ts
// хорошо
const { data } = await useFetch("/api/posts")
```

```ts
// плохо: двойной запрос
const data = await $fetch("/api/posts")
```

`$fetch` уместен в обработчике события и в серверном коде, где гидратации нет.

### Ключ useAsyncData задавай явно

Автоматический ключ выводится из имени файла и номера строки, поэтому переносом кода можно тихо поменять кеширование.

```ts
// хорошо
const { data } = await useAsyncData(`post-${route.params.id}`, () =>
  $fetch(`/api/posts/${route.params.id}`),
)
```

```ts
// плохо: ключ поменяется при переносе строки
const { data } = await useAsyncData(() => $fetch(`/api/posts/${id}`))
```

### await перед useFetch решает, блокировать ли навигацию

Это не про доступность данных, а про то, ждёт ли переход. Критичное и нужное для поисковиков грузи с `await`, остальное с `lazy: true`.

```ts
// хорошо
const { data: post } = await useFetch(`/api/posts/${postId}`)
const { data: comments } = await useFetch("/api/comments", { lazy: true })
```

```ts
// плохо: переход ждёт комментарии, которых на первом экране не видно
const { data: post } = await useFetch(`/api/posts/${postId}`)
const { data: comments } = await useFetch("/api/comments")
```

Уменьшить payload гидратации помогают `pick` и `transform`: без них в HTML уезжает весь ответ.

### Автоимпорт видит только верхний уровень

Сканируются `app/composables/*` и `app/utils/*` без вложенности. Разложенное по подпапкам не подхватывается.

```ts
// хорошо: реэкспорт из composables/index.ts
export * from "./cart/useCart"
```

```ts
// плохо: app/composables/cart/useCart.ts не подхватится
```

В `shared/` автоимпортируются только `shared/utils/*` и `shared/types/*`, и оттуда нельзя импортировать ни код Vue, ни код Nitro.

В этом проекте `ref`, `computed` и прочее из `vue` импортируются явно, несмотря на автоимпорт. Следуй существующему коду.

## Привязано к версии

Изменилось между третьей и четвёртой версиями. Ломается молча: путь существует, но ведёт не туда, а лишний аргумент просто игнорируется.

| Было в третьей | Стало в четвёртой |
| --- | --- |
| корень исходников в корне репозитория | `app/` |
| `~` и `@` ведут в корень репозитория | ведут в `app/` |
| для корня отдельного алиаса не требовалось | `~~` и `@@` |
| общий код раскладывался вручную | каталог `shared/` плюс алиасы `#shared` и `#server` |
| `useRuntimeConfig(event)` в серверном роуте | `useRuntimeConfig()` без аргумента |

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| `~/server/...` | `~~/server/...` | `~` ведёт в `app/`, а `server/` лежит в корне |
| `ref` на уровне модуля в композабле | `useState` | на сервере состояние общее для всех запросов |
| `await` перед `useRoute` или `useRuntimeConfig` | все композаблы Nuxt до первого `await` | после await контекст потерян |
| `$fetch` в setup | `useFetch` | запрос уйдёт дважды |
| `useAsyncData` без ключа | явный ключ, в том числе параметризованный | автоключ зависит от файла и строки |
| `useAsyncData(() => store.fetchUser())` для побочного эффекта | `callOnce` | `useAsyncData` про данные, а не про действия |
| `localStorage` для настроек при SSR | `useCookie` | на сервере `localStorage` не существует |
| `components: ['~/components', ...]` с дефолтом первым | дефолтная запись последней | иначе префиксные записи не срабатывают |
| `useRuntimeConfig(event)` в серверном роуте | `useRuntimeConfig()` без аргумента | в четвёртой версии аргумент убран |
| плагины без префикса при важном порядке | числовой префикс `01.analytics.ts` | порядок иначе не определён |
