# provide и inject

Читается из [SKILL.md](./SKILL.md), когда состояние передаётся вниз по дереву мимо пропсов.

Механизм удобен и опасен тем же: связь между поставщиком и потребителем не видна ни в одном из них. Правила ниже про то, как сделать её видимой и защитить состояние от произвольных правок откуда угодно.

## Ключ типизированный, не строка

Строковый ключ не даёт ни автодополнения, ни проверки типа, ни поиска по коду. `InjectionKey` решает всё три задачи сразу и не стоит ничего в рантайме.

```ts
// хорошо: ключ и тип объявлены рядом, в общем файле
import type { InjectionKey, Ref } from "vue"

export type CartContext = {
  readonly items: Ref<readonly Item[]>
  addItem: (item: Item) => void
}

export const cartKey: InjectionKey<CartContext> = Symbol("cart")
```

```ts
// плохо: тип на стороне потребителя приходится назначать вручную
provide("cart", { items, addItem })
const cart = inject<CartContext>("cart")
```

Во втором варианте `inject` вернёт то, что вы попросили, независимо от того, что положили. Это `as` в другой одежде.

## Наружу отдавай readonly и явные действия

Отдав `ref` как есть, вы разрешили менять состояние из любого потомка. Найти, кто именно его поменял, потом нечем.

```ts
// хорошо: читать можно всем, менять только через названное действие
const items = ref<Item[]>([])

function addItem(item: Item) {
  items.value = [...items.value, item]
}

provide(cartKey, { items: readonly(items), addItem })
```

```ts
// плохо: любой потомок может items.value = []
provide(cartKey, { items, addItem })
```

Так граница становится видимой: в типе контекста перечислено всё, что снаружи разрешено делать, и это тот же принцип, что и `defineExpose` для компонента.

## Отсутствие контекста должно падать громко

`inject` без значения возвращает `undefined`, и ошибка всплывает где-то ниже, в виде обращения к полю у `undefined`. Оборачивай в функцию, которая бросает сразу и с внятным текстом.

```ts
// хорошо
export function useCart(): CartContext {
  const cart = inject(cartKey)
  if (!cart) {
    throw new Error("useCart вызван вне CartProvider")
  }

  return cart
}
```

```ts
// плохо: undefined уедет вниз и проявится в другом файле
const cart = inject(cartKey)
cart.addItem(item)
```

Композабл-обёртка заодно прячет сам ключ: потребители зовут `useCart()` и не знают ни про `inject`, ни про символ.

## Значение по умолчанию через фабрику

Для объектов и массивов дефолт передаётся фабрикой, иначе одно значение разделят все потребители. Ровно та же ловушка, что и в `withDefaults` у пропсов.

```ts
// хорошо
const settings = inject(settingsKey, () => ({ theme: "light" }), true)
```

```ts
// плохо: один объект на всех
const settings = inject(settingsKey, { theme: "light" })
```

Третий аргумент `true` означает, что второй это фабрика, а не готовое значение.

## Реактивность не появляется сама

Передав примитив, вы передали снимок. Потребитель не узнает об изменении никогда.

```ts
// хорошо
const theme = ref<Theme>("light")
provide(themeKey, { theme: readonly(theme) })
```

```ts
// плохо: потребитель получит "light" навсегда
provide(themeKey, { theme: theme.value })
```

## Вызов только синхронно в setup

И `provide`, и `inject` работают, пока есть активный экземпляр компонента. После `await` в обычной функции его уже нет.

```ts
// хорошо
const cart = useCart()
const settings = await loadSettings()
```

```ts
// плохо: контекст потерян, inject вернёт undefined
const settings = await loadSettings()
const cart = useCart()
```

## Когда provide не нужен

Соблазн большой, а поводов мало. Проверь по порядку, прежде чем заводить контекст.

- состояние нужно одному потомку: обычный проп
- потомок один, но глубоко: тоже проп, либо пересборка дерева
- состояние нужно всему приложению и не привязано к поддереву: в Nuxt это `useState`, вне Nuxt композабл с модульным состоянием
- состояние нужно поддереву, границы которого совпадают с компонентом-обёрткой: вот здесь `provide` и оправдан

Главный аргумент против: связь невидима. Компонент, который зовёт `useCart()`, нельзя вставить куда угодно, и об этом ограничении не сказано ни в его пропсах, ни в его типах. Поэтому чем меньше таких компонентов, тем лучше, а имя провайдера должно быть в названии обёртки.

## Отладка

Найти, кто предоставил значение, из потребителя невозможно: инструменты разработчика показывают инъекции, но не путь до поставщика. Поэтому имя символа берётся осмысленным (`Symbol("cart")`, а не `Symbol()`), а ключ и тип живут в одном файле, по которому легко искать.
