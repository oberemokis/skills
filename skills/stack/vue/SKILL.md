# Vue

> Точка входа: [skills/core](../../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: Vue 3.5.34. Только Composition API и `<script setup lang="ts">`. Options API, JSX и render-функции в проектах не используются, правил про них здесь нет.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней: если в `package.json` версия другая, сверь имена до того, как напишешь.

## Соглашения проекта

Выведены из существующего кода, следуй им, даже если документация предлагает иначе.

- `ref`, `computed`, `watch`, `nextTick` импортируются явно из `vue`, в том числе в Nuxt, где они автоимпортируются
- пропсы не деструктурируются, обращение через `props.x`
- обработчики объявляются как `function onClick()`, не как `const onClick = () => {}`
- ссылки на элементы через `ref<HTMLElement | null>(null)` плюс атрибут `ref="name"`
- состояние, которому реактивность не нужна, остаётся обычным `let` вне `ref`
- у интерактивных элементов есть `aria-label` или доступное имя, у декоративных `aria-hidden`

## Когда применять

- пишешь или правишь `.vue`, композабл, реактивное состояние
- компонент ведёт себя не так, как ожидалось: значение не обновилось, событие пришло дважды, ссылка на элемент пустая
- решаешь, где держать состояние и как передать его между компонентами

## Когда НЕ применять

- страницы, роутинг, загрузка данных, серверная часть: это `nuxt` и `nitro`
- классы в разметке, темы, отступы: это `tailwind`
- как тестировать компонент: это `test`, форма теста определяется швом
- Options API и JSX: сознательно не покрываем

## Правила

### Объект в defineModel заменяй, не мутируй

Мутация вложенного поля не эмитит `update:*`, и родитель не узнаёт об изменении.

```ts
// хорошо
model.value = { ...model.value, name: next }
model.value = { ...model.value, items: [...model.value.items, item] }
```

```ts
// плохо: emit не произойдёт, родитель останется со старым значением
model.value.name = next
model.value.items.push(item)
```

Два присваивания подряд в одном тике читают устаревший `model.value`. Собирай изменения в одно присваивание.

### Объявляй emits, даже если просто пробрасываешь событие

Необъявленное событие попадает в `$attrs` и проваливается на корневой элемент. Обработчик родителя срабатывает дважды: один раз от `$emit`, второй от провалившегося слушателя.

```ts
// хорошо
const emit = defineEmits<{ click: [event: MouseEvent] }>()
```

```ts
// плохо: в шаблоне @click="$emit('click', $event)" без defineEmits
// родительский обработчик вызовется два раза
```

### Геттер computed без побочных эффектов

Только вычисление. Всё остальное в watch или в хук жизненного цикла.

```ts
// хорошо
const total = computed(() => items.value.length)

watch(total, (itemCount) => (document.title = `${itemCount} позиций`), {
  immediate: true,
})
```

```ts
// плохо: геттер меняет состояние
const total = computed(() => {
  visitCount.value++

  return items.value.length
})
```

```ts
// плохо: геттер ходит в сеть и возвращает промис
const user = computed(async () => (await fetch("/api/user")).json())
```

Асинхронный `computed` синтаксически проходит и возвращает промис, поэтому ошибка проявится не сразу.

### Читаешь DOM в watch, ставь flush post

По умолчанию колбэк выполняется до обновления DOM, поэтому чтение даёт старое состояние.

```ts
// хорошо
watch(messages, () => scrollToBottom(), { flush: "post" })
watchPostEffect(() => list.value?.scrollTo(0, list.value.scrollHeight))
```

```ts
// плохо: прочитает предыдущую высоту
watch(messages, () => list.value?.scrollTo(0, list.value.scrollHeight))
```

Симптом выглядит как гонка, и рефлекс подсказывает обернуть в `nextTick`. Правильный ответ это `flush: "post"`, подробности в [REACTIVITY.md](./REACTIVITY.md).

### Ссылка на элемент пуста до монтирования и при v-if

Тип всегда с `| null`, обращение через `?.`, чтение не раньше `onMounted`.

```ts
// хорошо
const input = ref<HTMLInputElement | null>(null)
onMounted(() => input.value?.focus())
```

```ts
// плохо: TypeError, когда элемент скрыт v-if
const input = ref<HTMLInputElement>()
watchEffect(() => input.value.focus())
```

Если ссылка нужна постоянно, `v-show` вместо `v-if` решает проблему в корне. Порядок ссылок в `v-for` не гарантирован, сопоставление по индексу ломается при переупорядочивании: см. [TEMPLATE-REFS.md](./TEMPLATE-REFS.md).

### Отсутствующий boolean-проп равен false, а не undefined

Vue кастует boolean-пропы, поэтому ветка на `undefined` мёртвая, хотя TypeScript выводит `boolean | undefined`.

```ts
// хорошо: дефолт объявлен явно
const props = withDefaults(defineProps<{ disabled?: boolean }>(), {
  disabled: false,
})
```

```ts
// плохо: ветка мертва, Vue уже подставил false
const props = defineProps<{ disabled?: boolean }>()
if (props.disabled === undefined) applyDefault()
```

Нужны именно три состояния, объявляй тип `boolean | null` и дефолт `null`. Массивы и объекты в `withDefaults` передавай фабрикой (`items: () => []`), иначе одно значение разделят все экземпляры компонента.

### Композабл вызывается синхронно в setup

Внутри условия, цикла, колбэка или после `await` в обычной функции хуки жизненного цикла не регистрируются. Состояние остаётся неинициализированным, слушатели не снимаются.

```ts
// хорошо
const url = ref("/api/default")
const { data } = useFetch(url)
onMounted(async () => (url.value = (await loadConfig()).apiUrl))
```

```ts
// плохо
if (needed) { const { user } = useAuth() }
for (const u of urls) useFetch(u)
```

Имя начинается с `use`, возвращается обычный объект с ref-ами, а не `reactive`: из `reactive` нельзя деструктурировать без потери реактивности.

### Math.random и new Date в рендере ломают гидратацию

На сервере и клиенте получаются разные значения. Считай на сервере детерминированно, недетерминированное переноси в `onMounted`.

```vue
<!-- хорошо -->
<span>{{ formatted }}</span>
```

```vue
<!-- плохо -->
<span>{{ new Date().toLocaleTimeString() }}</span>
<div :id="`field-${Math.random()}`" />
```

Разбор текстов ошибок гидратации и `data-allow-mismatch` в [SSR.md](./SSR.md).

## Привязано к версии

Переименований в 3.5 нет, все правила выше поведенческие. Зато есть возможности, появившиеся в 3.5: в обучающих данных они встречаются редко, поэтому сама модель их не предложит.

| Возможность | Зачем нужна |
| --- | --- |
| `onWatcherCleanup(fn)` | отменить запрос внутри `watchEffect` без самодельного флага |
| `watch(src, cb, { deep: 2 })` | ограничить глубину вместо полного обхода дерева |
| `watch(src, cb, { once: true })` | одноразовый наблюдатель без ручного `stop` |
| `<Teleport defer>` | цель, которой ещё нет в DOM, без `nextTick` |
| `useTemplateRef("name")` | связать ссылку с атрибутом по строке, а не по совпадению имени переменной |
| деструктуризация пропсов с дефолтами | заменяет `withDefaults` и фабрики |

Последние две в проекте пока не используются: ссылки объявляются через `ref` с атрибутом `ref="name"`, дефолты через `withDefaults`. Следуй существующему коду, а не таблице.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| `v-if` и `v-for` на одном элементе | фильтр в `computed`, либо `v-if` внутри `<template v-for>` | в Vue 3 `v-if` вычисляется первым, переменная цикла ещё не существует |
| деструктуризация `reactive` | `ref`, либо `toRefs` | деструктуризация снимает прокси, значение перестаёт обновляться |
| сравнение `reactive`-объекта через `===` | сравнение по идентификатору, либо `toRaw` | прокси не равен исходному объекту, сравнение всегда ложно |
| мутация состояния в геттере `computed` | watch | геттер вызывается при пересчёте, мутация даёт непредсказуемый порядок |
| `fetch` в `computed` | watch или хук жизненного цикла | вернётся промис, а зависимости отследятся неверно |
| `computed`, возвращающий новый объект каждый раз | вернуть предыдущую ссылку, если значения совпали | подписчики пересчитываются, хотя данные не изменились |
| `shallowRef` для примитивов | `ref` | для примитивов они идентичны, `shallowRef` оправдан только на больших объектах, заменяемых целиком |
| `withDefaults` с массивом или объектом напрямую | фабрика `() => []` | одно значение разделяется между всеми экземплярами компонента |
| деструктуризация пропсов, даже реактивная из 3.5 | `const props = defineProps<…>()` и обращение через `props.x` | в проекте так не пишут, а на границе с обычной деструктуризацией легко потерять реактивность |
| `flush: "sync"` в watch | `"pre"` по умолчанию, `"post"` для DOM | синхронный режим срабатывает на каждую мутацию без батчинга |
