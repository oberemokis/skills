# Пропсы, события, defineModel

Читается из [SKILL.md](./SKILL.md) при проектировании интерфейса компонента.

## Объявление пропсов

Только типовая форма, без рантайм-валидации. Массивы на входе помечаются `readonly`: компонент их не меняет, и это видно из подписи.

```ts
// хорошо
const props = defineProps<{
  images: readonly string[]
  alt: string
  variant?: "solid" | "ghost"
}>()
```

```ts
// плохо: рантайм-объявление теряет типы и допускает мутацию
const props = defineProps({
  images: { type: Array, required: true },
})
```

Пропсы не деструктурируются, обращение идёт через `props.x`. Реактивная деструктуризация из 3.5 работает, но выглядит ровно как обычная, которая реактивность снимает, и по виду строки эти два случая не различить. Через `props.x` неоднозначности нет.

## Дефолты

```ts
// хорошо
const props = withDefaults(
  defineProps<{ variant?: "solid" | "ghost"; items?: readonly Item[] }>(),
  {
    variant: "solid",
    items: () => [],
  },
)
```

```ts
// плохо: одно значение разделят все экземпляры компонента
const props = withDefaults(defineProps<{ items?: Item[] }>(), {
  items: [],
})
```

Фабрика обязательна для всего, что не примитив: массив, объект, `Map`, `Set`, `Date`. Симптом ошибки узнаваемый: выбрали строку в одной таблице, она выделилась во всех.

## Boolean-пропы

Отсутствующий boolean-проп равен `false`, а не `undefined`: Vue кастует такие пропы. TypeScript при этом выводит `boolean | undefined`, поэтому ветка на `undefined` компилируется и никогда не выполняется.

```ts
// хорошо: дефолт объявлен явно
const props = withDefaults(defineProps<{ disabled?: boolean }>(), {
  disabled: false,
})
```

```ts
// плохо: мёртвая ветка
if (props.disabled === undefined) applyDefault()
```

Нужны три состояния, объявляй `boolean | null` с дефолтом `null`.

## События

Типовая форма с именованными кортежами. Старая форма с перегрузками читается хуже и не даёт имён аргументам.

```ts
// хорошо
const emit = defineEmits<{
  update: [value: string]
  close: []
}>()
```

```ts
// плохо
const emit = defineEmits<{
  (event: "update", value: string): void
  (event: "close"): void
}>()
```

## Необъявленное событие срабатывает дважды

Это самая дорогая ловушка раздела. Необъявленное событие попадает в `$attrs` и проваливается на корневой элемент. Обработчик родителя вызывается дважды: один раз от `$emit`, второй от провалившегося слушателя.

```vue
<!-- хорошо: событие объявлено, в $attrs не попадёт -->
<script setup lang="ts">
const emit = defineEmits<{ click: [event: MouseEvent] }>()
</script>

<template>
  <button @click="emit('click', $event)">
    <slot />
  </button>
</template>
```

```vue
<!-- плохо: без defineEmits обработчик родителя вызовется два раза -->
<template>
  <button @click="$emit('click', $event)">
    <slot />
  </button>
</template>
```

Третий вариант тоже верный: не переэмитить вообще и дать нативному слушателю провалиться на единственный корневой элемент. Тогда `defineEmits` не нужен, но и `$emit` в шаблоне быть не должно.

Объявление события это не документация, а переключатель поведения проваливания. Именно поэтому его пропуск и даёт двойное срабатывание.

## defineModel

Значение достаётся и меняется как обычный `ref`, но с одним отличием: объект надо заменять, а не мутировать. Мутация вложенного поля не эмитит `update:*`, и родитель об изменении не узнаёт.

```ts
// хорошо
model.value = { ...model.value, name: nextName }
model.value = { ...model.value, items: [...model.value.items, item] }
```

```ts
// плохо: emit не произойдёт
model.value.name = nextName
model.value.items.push(item)
```

Два присваивания подряд в одном тике читают устаревший `model.value`, поэтому изменения собираются в одно присваивание.

Отдельная ловушка это дефолт. `defineModel({ default: 1 })` при отсутствии значения у родителя даёт рассинхрон: ребёнок работает с единицей, родительский `ref` остаётся `undefined`, и двусторонняя связь нарушена. Лечится инициализацией в родителе или `required: true`, а если дефолт нужен именно в ребёнке, оборачивай в `computed` с `get` и `set`.

## defineExpose

Компонент закрыт по умолчанию. Наружу отдаётся только то, что перечислено явно, и это правильно: чем меньше поверхность, тем меньше связанность.

```ts
// хорошо: наружу только метод, состояние остаётся внутри
defineExpose({ focus })
```

```ts
// плохо: родитель получил право писать в состояние ребёнка напрямую
defineExpose({ focus, value, isOpen, items })
```

Второй случай превращает внутреннее устройство компонента в его публичный интерфейс: переименовать `items` уже нельзя, не зная всех родителей.

Ссылка на компонент типизируется через `InstanceType`, и только на то, что выставлено: `ref<InstanceType<typeof ChildComponent> | null>(null)`.
