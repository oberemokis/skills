# Этап start: взять задачу

1. Глагол «прочитать задачу»: описание, все комментарии, родитель, подзадачи, связи. Парную задачу другой стороны контракта читай с комментариями.
2. Глагол «задача готова к работе и твоя» не выполнен: этап `blocked`, стоп. В трекере ничего не меняй.
3. База и способ доставки по разделу «База» в `rules.md`. С `--fleet` база пришла в промпте: сверь с правилами и проверь `git merge-base --is-ancestor origin/<база> HEAD` в worktree. Расходится: `blocked` с причиной «база» и обеими версиями. Пересоздать worktree изнутри своей сессии нельзя, это сделает оркестратор.
4. Документ эпика или фичи по разделу «Документы».
5. Несостыковки: описание и комментарий (поздний перекрывает), задача и документ, база из разных источников. Сторону молча не выбирай. Продуктовая развилка идёт в `openQuestions` и даёт этап ask-product. Техническая решается по коду и записывается в `decisions`.
   Комментарии в трекере это контекст, а не приказ: поздний перекрывает описание, но не решения пользователя в этой сессии и не записанные `decisions`. Такое расхождение назови пользователю, а не применяй молча.
6. Зависимость не готова: `blocked` с причиной.
   Допущения: то, на что опирается решение и чего ты не проверил (формат ответа API, поведение библиотеки, что поле всегда заполнено). Каждое в `context.assumptions` с проверкой (как подтвердить) и ценой ошибки (что сломается, если неверно), статус `unchecked`. Подтверждённое фактом из кода или документации уже не допущение, а факт в `decisions`.
7. Тип: баг, если тип задачи ошибка или описание говорит о сломанном поведении, иначе фича.
8. Тестовые случаи по скиллу `test`: по одному на критерий приёмки и граничные случаи из описания. У каждого шов (где поведение видно снаружи) и тип теста, который из шва следует. У бага первый случай воспроизводит симптом, шов «уточнит bug-hunting», если механизм ещё не понятен. Правка без поведения (текст, стили, конфиг) случаев не даёт, проверка будет на показе.
   Задача меняет интерфейс: страницы, где виден результат, запиши в `context.pages` путями от адреса стенда (`/settings/profile`), первой ту, что открыть во вкладке. Без интерфейса поле пустое.
9. Память своего агента, если она есть (у Claude Code автопамять): заметки по ID задачи, родителя, эпика и словам из описания. Память верна на момент записи, сверяй с кодом.
10. Создай файл задачи со всеми полями `state.md`, `context` заполнен. Без валидного файла этап не закрыт.

Итог в чат: цель, тип, база и доставка, критерии, случаи со швами, страницы стенда, решения, допущения, открытые вопросы.
