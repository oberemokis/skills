# Этап close: закрытие

Внешние шаги по разделу «Внешние шаги» в `state.md`.

1. Доставка: MR из `mrs` влит (глагол «найти MR по ветке») или коммит есть в `origin/<база>`. Нет: `blocked`.
2. Пайплайн базы после слияния: глагол «ждать пайплайн по SHA» с SHA своего слияния, а не «последний пайплайн ветки»: параллельные задачи вливаются рядом. На время ожидания «приостановил». Красный: `blocked`, статус задачи не менять.
3. Текст закрытия: что сделано по пунктам, автотесты с числами, сценарии показа, ревью и аудит (найдено, исправлено, принято как есть), коммит или MR.
4. Память: из сделанного выбери факты, которые переживут задачу. Общее (контракт, гоча для всех, решение с продуктом, общая команда): предложи место в документации проекта или тест, в git без подтверждения не пиши, коммит делает пользователь. Личное: в память своего агента (у Claude Code автопамять); у агента без памяти назови факт пользователю одной строкой. Прогресс, статусы, время и секреты никуда.
5. Вопрос «Закрыть задачу»: в `preview` текст закрытия и оба списка памяти. Ждать «закрыть».
6. Решение разошлось с описанием задачи или implement вернул правку описания: глагол «поправить описание», затем комментарий «было → стало».
7. Комментарий закрытия глаголом «оставить комментарий».
8. Статус глаголом «перевести после доставки».
9. Память записывается после «закрыть».
10. «Приостановил» в последний раз. Время по правилам трекера из `rules.md`; спорный отрезок из `flag` назови в итоге.
11. Worktree и ветку не удаляй и не предлагай. Под `task-fleet` сессию закроет оркестратор.

Этап `done`, `stage.status = done`.
