# Этап show: дифф и показ

Одна остановка перед коммитом: пользователь видит дифф и результат в браузере вместе. После замечаний шаг повторяется целиком, поэтому в коммит уходит ровно тот дифф, который он одобрил.

## Стенд

Задача без интерфейса (только бэкенд, конфиг, CI): вместо браузера запрос к стенду или автотесты worktree, причина в итог. Раздел «Стенд» в `rules.md` говорит, что стенд проекта видит, а что нет.

Стенд, порт и вкладка по [stand.md](../stand.md). У задачи с интерфейсом они обычно подняты ещё на implement.

## Сценарии

1. По одному на критерий приёмки, на L плюс граничные случаи и соседнее поведение. Сценарии с интерфейсом идут во вкладке из `stand.md`, пользователь видит клики. Скриншоты сохраняй вне worktree.
2. Сценарий не прошёл: чини, затем verify (он перепишет результаты случаев и `verifiedDiff` под новый дифф) и сценарий заново.

## Дифф

Признак «в Herdr» проверь заново по разделу «Дифф» `SKILL.md`: окно могли закрыть.

В Herdr дифф в панели Review. Панель запоминает выбранную область для репозитория и может стоять на «Uncommitted», поэтому в вопросе попроси выбрать «vs <база>».

Не в Herdr дифф в gitone по разделу «Дифф» [worktree.md](worktree.md). Ветка уже с коммитом (круг исправлений после доставки), а gitone открыт без аргументов: он показывает только новые правки, для круга этого хватает. Полный дифф ветки дай в вопросе командой `gitone $(git merge-base origin/<база> HEAD)`, новые файлы (`git ls-files --others --exclude-standard`) перечисли: с аргументами gitone их не показывает.

## Вопрос

«Посмотри дифф и результат в браузере», с тем, где дифф: панель Review с «vs <база>» или команда gitone. В `preview`: сценарии с результатом, пути к скриншотам, diffstat, новые файлы.

- «Всё верно, доставлять» (рекомендую).
- «Есть замечания»: текстом через «Другое».
- «Замечания пришлю из Review»: только в Herdr. Пока открыт вопрос, Review сессии не пишет: агент с вопросом для Herdr заблокирован.
- «Остановить».

Замечания текстом: в `findings` с `source: show`, затем implement, verify и этот шаг заново.

«Замечания пришлю из Review»: `waiting-user` с `stage.waiting` «замечания из Review» и «приостановил», как перед вопросом, затем ход закончи без вопроса. Дальше по пришедшему сообщению:

- в нём есть строка `Code review of <путь worktree>` (перед ней может стоять заметка пользователя): это замечания, каждое в `findings` с `source: show`, затем implement, verify и этот шаг заново;
- «Ask about diff» и вопросы по строкам (`The diff of …`, `In <файл>, lines …`): ответь и жди дальше, шаг не повторяется;
- одобрение текстом («ок», «доставляй»): как «Всё верно, доставлять».

После одобрения запиши `reviewedDiff`: `node <папка скилла>/scripts/fingerprint.mjs <база> <worktree>`. Он должен совпасть с `verifiedDiff`: не совпал, значит после автотестов была правка, и до вопроса нужен verify. Погаси стенд и закрой вкладку по `stand.md`, чтобы отпустить порт.
