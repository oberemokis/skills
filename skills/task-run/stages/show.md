# Этап show: дифф и показ

Одна остановка перед коммитом: пользователь видит дифф и результат в браузере вместе. После замечаний шаг повторяется целиком, поэтому в коммит уходит ровно тот дифф, который он одобрил.

## Стенд

Задача без интерфейса (только бэкенд, конфиг, CI): вместо браузера запрос к стенду или автотесты worktree, причина в итог. Раздел «Стенд» в `rules.md` говорит, что стенд проекта видит, а что нет.

Стенд, порт и вкладка по [stand.md](../stand.md). У задачи с интерфейсом они обычно подняты ещё на implement.

## Сценарии

1. По одному на критерий приёмки, на L плюс граничные случаи и соседнее поведение. Сценарии с интерфейсом идут во вкладке из `stand.md`, пользователь видит клики. Результат каждого сценария с интерфейсом снимай с красной рамкой по разделу «Скриншот с рамкой» в `stand.md`, в папку `~/Documents/task-run/<проект>/<ID>/show` рядом с кругами визуального ревью. В worktree, временной папке или папке состояния скриншот пользователь не найдёт. Перед вопросом открой папку: `open <папка>`.
2. Сценарий не прошёл: чини, затем verify (он перепишет результаты случаев и `verifiedDiff` под новый дифф) и сценарий заново.

## Вопрос

«Посмотри дифф и результат в браузере». В `preview`: сценарии с результатом, пути к скриншотам, diffstat (`git diff --stat <точка>` с точкой из `scripts/fingerprint.mjs --point <база> <worktree>`, вместе с незакоммиченным), новые файлы (`git ls-files --others --exclude-standard`).

- «Всё верно, доставлять» (рекомендую).
- «Есть замечания»: текстом через «Другое».
- «Остановить».

Замечания: в `findings` с `source: show`, затем implement, verify и этот шаг заново.

После одобрения запиши `reviewedDiff`: `node <папка скилла>/scripts/fingerprint.mjs <база> <worktree>`. Он должен совпасть с `verifiedDiff`: не совпал, значит после автотестов была правка, и до вопроса нужен verify. Погаси стенд и закрой вкладку по `stand.md`, чтобы отпустить порт.
