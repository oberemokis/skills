# Этап deliver: доставка

Каждый внешний шаг идёт по разделу «Внешние шаги» в `state.md`: сначала посмотреть, не сделано ли уже, затем `pending`, действие, `outbound`.

1. Проверки до коммита: ветка в worktree это ветка задачи; show одобрен; отпечаток `scripts/fingerprint.mjs` равен `reviewedDiff` и `verifiedDiff`; у каждого случая `context.cases` есть `result` с этим же `diff` и статусом `pass` или `not_applicable`. Отпечаток не равен `reviewedDiff`: вернись к show. Не равен `verifiedDiff` или у случая нет текущего `pass`: вернись к verify. В обоих случаях ничего не коммить. `reviewedDiff` старого вида (до скрипта) с отпечатком не совпадёт никогда: это возврат к show, а не ошибка.
2. Коммит скиллом `commit`: он покажет файлы и сообщение и ждёт подтверждения. Первая строка по шаблону `commit` из `project.json`, он перекрывает запрет скилла на префикс задачи. У бага причина из `cause` в теле. Хуки не обходить. SHA в `commit`.
3. Push своей ветки явным refspec: `git push origin <ветка>:<ветка>`. При `delivery: local` push нет совсем.
4. `delivery: push` (в общую ветку, например эпика):
   - подтверждение на push;
   - `git fetch origin`, `git rebase origin/<база>`. Rebase принёс правки в затронутые файлы: вопрос, повторить ли автотесты;
   - `git push origin HEAD:<база>`. Отказ non-fast-forward: fetch и rebase ещё раз, второй отказ значит стоп.
5. `delivery: mr`:
   - глагол «найти MR по ветке» со всеми статусами. Есть открытый: возьми его, есть влитый: доставка уже сделана. Иначе глагол «открыть MR», номер в `mrs`;
   - «приостановил», `waiting-external` «пайплайн MR», затем глагол «ждать пайплайн MR» фоновой командой. Сетевая ошибка опроса не красный пайплайн: повтори запрос;
   - красный: находка с `source: pipeline`, вопрос «Пайплайн упал». Исправление идёт через implement и verify, затем amend: перед ним ветка `backup/<ветка>-<n>`, после `git push --force-with-lease origin <ветка>:<ветка>`. Так держится один коммит на ветку. Force-push только в свою ветку задачи. Retry джобов не делать;
   - зелёным считается только пайплайн на SHA головы MR, и эта голова равна `commit`. Пайплайн прошлого коммита (до amend) или другой ветки не в счёт. Пайплайна на голове нет совсем: это не зелёный, а вопрос, ждать его или идти без CI;
   - зелёный: «начал работу», вопрос о слиянии. Слияние только после подтверждения, глаголом «влить MR».
6. `delivery: local`: коммит остаётся в ветке задачи на этой машине, без push и MR. Доставка на этом сделана: `done` с SHA в `commit`. Влить ветку в базу пользователь решит сам, вне задачи.
