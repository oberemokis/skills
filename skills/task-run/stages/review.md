# Этапы review и audit: ревью агентами и аудит пакета

## Ревью (M и L)

Дифф до доставки не закоммичен, поэтому:

1. Новые файлы задачи сделай видимыми для диффа: `git add -N <файл>` для каждой строки `??` из `git status --porcelain`.
2. Дифф: `git diff $(git merge-base HEAD origin/<база>)`, точным выводом (`ctx_shell` с `raw=true`, сжатый дифф теряет строки). Пустой: `blocked`.
3. Файлы распредели по областям `review` из `project.json`:
   - `with: review`: скилл `review`. У него `disable-model-invocation`, поэтому читай файл `<папка скилла>/../review/SKILL.md` и выполняй по шагам с диффом из шага 2. Агентов он запускает сам.
   - `with: code-review`: встроенный скилл `code-review` с уровнем (`medium` на M, `high` на L) и путём `<worktree>/<root>`. Без пути он ревьюит основную папку.
4. Файлы вне областей идут в итог блоком «не проверено».
5. Находки запиши в `findings` с `source: review` и уровнем. Этап файлы не правит.

## Аудит (по выбору в плане)

Скилл `audit`, файлом `<папка скилла>/../audit/SKILL.md`. На его вопросы отвечай сам: затронутый пакет целиком, оси кроме тестов (их проверило ревью). Находки в коде задачи идут в `findings`, остальные в текст закрытия. Чинить по аудиту в этой задаче нельзя.

## Возврат к реализации

Серьёзные находки (P1, P2, тесты уровней 1–2, «возможный дефект продукта»): вопрос «Исправить находки».

- «Исправить» (рекомендую): implement с открытыми `findings`, пункты «возможный дефект продукта» получают `bug: true`. Затем verify и повторное ревью всего диффа.
- «Принять как есть»: пункты `accepted`, они уйдут в текст закрытия.
- «Остановить».

Третий круг с серьёзными находками: вопрос «Этап не прошёл». Серьёзных нет: дальше show.
