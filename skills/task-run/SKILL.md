# Task run

> Точка входа: [core](../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: herdr 0.9.5 для работы под `work`, расширение Claude in Chrome для вкладки стенда, остальное от версий инструментов не зависит. Скилл ведёт одну задачу. Что делать на этапе, лежит в `stages/`, как это делается в конкретном проекте, лежит в папке проекта: [project.md](project.md).

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней.

## Когда применять

- пользователь вызвал `/task-run <ID>`, или `work` прислал такой промпт в сессию задачи
- нужно продолжить задачу, у которой уже есть файл состояния

## Когда НЕ применять

- несколько задач сразу: это `work`, он запускает этот скилл в сессии каждой задачи
- правка без задачи в трекере: маршрут без задачи не начинается, сначала задача
- ревью готового диффа без задачи: это `review`

## Правила

### Вызов

Аргументы: ID задачи; `--level S|M|L` перекрывает оценку; `--setup` заново собирает папку проекта. `--work` значит, что сессию запустил `work`: тогда в промпте есть ещё `--base`, `--branch` и `--worktree`, а worktree уже создан.

Пара `--minutes N --source user|tracker` несёт готовые минуты от `work`: не пересчитывай их. Задачу без минут начинает [task-estimate](../task-estimate/SKILL.md); он использует общие start, worktree и подготовку плана, затем передаёт готовый план на обычное подтверждение. `T1–T5` обозначает длительность; `--level S|M|L` задаёт глубину проверки.

Папка скилла это папка этого `SKILL.md` (Claude Code показывает её строкой «Base directory» при загрузке). Пути `stages/`, `scripts/` и `schemas/` ниже от неё.

Вид своего агента (`claude`, `codex`, `opencode`) и ID своей сессии нужны для файла задачи: у Claude Code ID лежит в `$CLAUDE_CODE_SESSION_ID`.

### Проект

Первым шагом запусти `node <папка скилла>/scripts/resolve-project.mjs`, передав `--project <имя>`, если оно пришло от `work` или пользователя. При `execution.mode=ssh` сначала прочитай [удалённый маршрут](remote.md). Его правила cwd, инструментов и стенда действуют на всех этапах и при продолжении. SSH напрямую без `work`: предложи `/work --project <имя> <ID>`, не создавай worktree в локальной сессии. Ответ JSON:

- `found`: прочитай `project.json` и `rules.md` из `dir`. Где `rules.md` спорит с инструкциями репозитория, прав `rules.md`: его писал пользователь под этот маршрут.
- `missing` или `broken`: с `--work` поставь задачу на стоп с причиной «нет папки проекта», опросник ведёт оркестратор. Без `--work` проведи опросник по [project.md](project.md).

Затем проверь подключения командами из `tracker.check` и `codeHost.check`. Не отвечают: стоп, назови, что именно, и дай команду из раздела «Подключения» в `project.md`. Ничего наружу до этого не делай.

Действия с трекером и код-хостом называются глаголами: «прочитать задачу», «начал работу», «приостановил», «открыть MR» и так далее. Как глагол выполняется в этом проекте, написано в `rules.md`. Глагола там нет: стоп и вопрос, а не догадка.

### Состояние

Файл `<dir>/tasks/<ID>.json`, формат и запись в [state.md](state.md). Пишет его только сессия этой задачи и только через проверку: запись файла во временный `<ID>.json.tmp`, затем `node <папка скилла>/scripts/check-json.mjs --commit <ID>.json.tmp`. Проверка не прошла: исправь файл, этап не закрыт.

Файл есть при старте: это продолжение, порядок в разделе «Продолжение» `state.md`.

### Стенд и вкладка

У задачи с интерфейсом стенд и вкладка браузера поднимаются с первой правки интерфейса и живут до одобрения показа: [stand.md](stand.md).

### Маршрут

| Код | Этап | Описание |
|---|---|---|
| start | Взять задачу | [stages/start.md](stages/start.md) |
| worktree | Рабочая копия | [stages/worktree.md](stages/worktree.md) |
| plan | План | [stages/plan.md](stages/plan.md) |
| ask-product | Вопрос продукту | [stages/ask-product.md](stages/ask-product.md) |
| implement | Реализация | [stages/implement.md](stages/implement.md) |
| verify | Автотесты | [stages/verify.md](stages/verify.md) |
| review, audit | Ревью и аудит | [stages/review.md](stages/review.md) |
| show | Дифф и показ | [stages/show.md](stages/show.md) |
| deliver | Доставка | [stages/deliver.md](stages/deliver.md) |
| close | Закрытие | [stages/close.md](stages/close.md) |

Входя в этап, читай его файл и делай по нему. Этап, которого нет в плане, не запускается.

| Этап | S | M | L |
|---|---|---|---|
| verify | затронутые проверки | затронутый набор целиком | всё |
| review | нет | да | да |
| audit | нет | по выбору в плане | предлагается в плане |
| show | сценарии по критериям | то же | плюс граничные случаи и соседнее поведение |

Уровень: S, если оценка до часа, до двух файлов и нет API, контракта, миграции, новой логики; L, если оценка от дня, меняется контракт или API, задеты несколько пакетов, открыт вопрос продукту или задача зависит от соседних; иначе M. `--level` перекрывает оценку.

### Ход

- Перед этапом: в файле `stage` с этим кодом и `running`, глагол «начал работу», если флаг сейчас снят. У новой задачи под `--work` до первого «начал работу» прочитай уже списанные минуты по правилам проекта, если доступны. Сохрани в `estimateIntake.spentBefore` при первой записи; неизвестное не заменяй нулём.
- После этапа: статус этапа по итогу (`done`, `skipped`, `blocked`), запись файла, одна строка в чат: `<ID> · Автотесты: 212 прошло, 0 упало → Ревью`.
- Между этапами вопросов нет. Вопросы только из файлов этапов и при стопе.

### Вопросы и ожидание

Вопрос задаётся инструментом вопросов своего агента, в Claude Code это AskUserQuestion. Инструмента нет: тот же вопрос текстом с вариантами, после записи ожидания (ниже). Пользователь может видеть только окно вопроса, поэтому вопрос понятен сам по себе.

- `header`: ID задачи. Вопрос простыми словами: что уже сделано (одна фраза с цифрами), что дальше, сам вопрос. Этапы называй по-русски, без кодов, полей и путей.
- Вариантов от двух до четырёх, рекомендуемый первым с пометкой «(рекомендую)». У каждого описание: что произойдёт и что увидят другие (push, MR, слияние, комментарий, статус в трекере).
- Решение про текст (вопрос продукту, сообщение коммита, описание MR, текст закрытия, список находок) показывает текст целиком в `preview` варианта «Отправить» или «Подтвердить».
- Ответ «Другое» выполняй как есть и не переспрашивай.

Перед каждым вопросом, в том числе текстовым (попросить запустить `humanizer` или `grill`), сессия:

1. пишет в файл `stage.status = waiting-user` и `stage.waiting` одной строкой: чего ждём;
2. выполняет глагол «приостановил»: пока задача ждёт человека, время в трекере не копится.

Уведомлять не надо: herdr сам подсвечивает пространство, когда сессия открыла вопрос или закончила ход.

После ответа: `running`, «начал работу». Ожидание внешнего (пайплайн, ответ продукта): `waiting-external`, «приостановил».

### Подтверждения

Ждать ответа и дальше не идти:

- отправка вопроса продукту;
- push в общую ветку (базу, ветку эпика);
- коммит и всё после него, пока пользователь не одобрил шаг «Дифф и показ»;
- гипотезы бага до их проверки;
- слияние MR;
- закрытие задачи.

MR и push своей ветки задачи отдельного подтверждения не требуют: это ещё не слияние. Наружу не делать никогда: прод, force-push в общие ветки, чужие ветки и MR, Retry и ручные джобы, задачи других людей. Force-push своей ветки только по `stages/deliver.md`.

### Стоп

Остановись, напиши причину в итог и поставь этап `blocked`, если:

- задача не готова к работе или не твоя;
- зависимость не готова (другая задача, ответ продукта);
- нужна миграция, новая зависимость, правка API или контракта, а плана на это не было;
- проверка красная и не чинится за две попытки;
- конфликт rebase или merge (сначала `--abort`);
- команду режут права или песочница агента: не обходить, назвать нужное разрешение;
- стенд не поднимается за две попытки.

При стопе и остановке погаси свой стенд и закрой вкладку: порт нужен другим задачам ([stand.md](stand.md)). Затем, до записи статуса в файл, передача handoff по разделу «Передача при уходе» в [state.md](state.md): задачу может продолжить другой агент.

### Остановка и продолжение

Пользователь просит остановиться: передача handoff, затем `stage.status = stopped`, «приостановил», итог одной строкой. `work` такую задачу сам не поднимает. Продолжить можно тем же вызовом `task-run <ID>`, в том числе из другого агента через `work`.

### Субагенты

Этап ведёт сессия задачи. Отдать часть работы субагенту стоит, когда это окупается: длинный прогон тестов, чтобы логи не раздували контекст, или независимый взгляд на дифф. Субагент получает самодостаточный промпт с путём worktree и `context` задачи, не пишет в трекер и код-хост, не коммитит, не спрашивает пользователя и не пишет файл состояния. Модель не передавай, она наследуется. Его ответ сверяй с кодом и выводом команд.

## Привязано к версии

- herdr 0.9.5: `HERDR_PANE_ID` и `HERDR_WORKSPACE_ID` в окружении панели, но они наследуются во всё, что из неё запущено, поэтому хост решает `host.mjs`; вопрос и конец хода агента herdr видит сам.
- Claude in Chrome: вкладку открывает `tabs_create_mcp`, закрывает `tabs_close_mcp`; ID вкладок из другой сессии недействительны.
- Playwright 1.62: `shots.mjs` берёт `playwright`, `@playwright/test` или `playwright-core` из проекта, своего пакета у скилла нет; браузер свой chromium, без него установленный Chrome.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| писать `<ID>.json` напрямую | временный файл и `check-json.mjs --commit` | неполный файл ломает продолжение, как случилось с файлом без `context` |
| вопрос текстом без `stage.waiting` | `waiting-user`, «приостановил» | оркестратор и трекер не узнают, что задача ждёт |
| повторить внешний шаг после падения | сверка с миром по `state.md` | дубли MR, комментариев и вопросов продукту |
| флаг «в работе» во время ожидания человека | «приостановил» перед вопросом | три ждущие задачи копят тройное время |
| коммит после правки, которую пользователь не видел | шаг «Дифф и показ» заново | в коммит уходит непросмотренный дифф |
| угадать, как глагол работает в трекере | глагол из `rules.md` или вопрос | чужой трекер устроен иначе, догадка пишет мусор людям |
| `EnterWorktree` при `--work` | работать в текущей папке | сессия уже в worktree, вход создаст вложенную копию |
| поднять стенд только на показе у задачи с интерфейсом | стенд и вкладка с первой правки интерфейса | пользователь видит работу, пока её дёшево поправить |
| вопрос про занятый порт на implement | работать без вкладки до показа | порт освободится сам, вопрос останавливает реализацию |
