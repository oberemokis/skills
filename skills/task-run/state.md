# Файл задачи

Файл `<папка проекта>/tasks/<ID>.json`, схема `schemas/task.schema.json`. Он хранит решения и прогресс маршрута. Истина о задаче в другом месте, и при расхождении права она, в таком порядке: git и код-хост, затем трекер, файл последним.

## Поля

- `schema`: всегда `task-run/task@1`. `plugin`: версия и папка плагина, на котором начата задача; только у задач до отказа от плагина, у новых поля нет.
- `project`, `task`, `title`, `type` (`feature` или `bug`), `level`, `levelReason`.
- `base`, `delivery` (`mr` или `push`), `branch`, `worktree` (абсолютный путь), `fleet`.
- `session`: `agent` это адрес терминала hc (`$HC_TERMINAL_ID`), а не вид агента, только если `scripts/host.mjs` ответил `hc`, иначе `null`; `agentKind` это вид агента (`claude`, `codex`, `opencode`), `agentSession` это ID его сессии (у Claude `$CLAUDE_CODE_SESSION_ID`); `claudeSession` тот же ID у Claude и `null` у других агентов, его читают файлы, начатые до `agentKind`; `workspace` и `pane` всегда `null`, пространство и вкладка лежат в метках терминала. Файла без `agentKind` вёл Claude.
- `stage`: текущий этап, его состояние (`running`, `waiting-user`, `waiting-external`, `blocked`, `stopped`, `done`), `waiting` одной строкой и `since`. По `stage` оркестратор понимает, что с задачей, не читая экран.
- `stages`: каждый этап один раз, статус и время, короткая `note`. Статус меняется заменой значения.
- `context`: итог этапа start. Цель, критерии приёмки, тестовые случаи со швами, решения, открытые вопросы, документ эпика, имена заметок памяти, страницы стенда для вкладки (`pages`, у задачи без интерфейса пусто или нет). Продолжение в новой сессии берёт его отсюда.
- `findings`: находки ревью, аудита, показа и красного пайплайна, со статусом `open`, `fixed` или `accepted`. Пункт с `bug: true` идёт через `bug-hunting`.
- `hypothesis`, `cause`: выбранная гипотеза бага и причина одной фразой для сообщения коммита.
- `fixRounds`: число завершённых кругов исправлений. Растёт, когда круг закончен, а не когда начат.
- `flag`: флаг «в работе» и с какого времени он стоит. Нужен, чтобы при закрытии назвать подозрительный отрезок времени.
- `pending`, `outbound`: намерение внешнего действия и журнал сделанных (раздел «Внешние шаги»).
- `context.assumptions`: непроверенные опоры решения, у каждой проверка, цена ошибки и статус (`unchecked`, `confirmed`, `refuted`).
- `context.cases[].result`: итог проверки случая на конкретном диффе (статус, отпечаток, время, команда, причина для `not_run` и `not_applicable`). Отпечаток считает `scripts/fingerprint.mjs`: правка любого файла задачи меняет его, и результат со старым отпечатком перестаёт быть текущим.
- `verifiedDiff`: отпечаток диффа, на котором последний раз прошли все автотесты этапа verify.
- `reviewedDiff`: отпечаток диффа, который пользователь одобрил на шаге «Дифф и показ».
- `commit`, `mrs`: SHA коммита задачи и список MR (их бывает больше одного).

## Когда писать

Первый раз в конце этапа start, когда `context` собран. Дальше при каждой смене этапа, перед и после каждого внешнего шага, перед вопросом и после ответа. Запись только через `check-json.mjs --commit`.

## Внешние шаги

Всё, что видят другие (push, MR, слияние, комментарий, статус, вопрос продукту), делается так:

1. Посмотри на мир: не сделано ли это уже. MR по ветке со всеми статусами, влит ли MR, есть ли твой комментарий после `stage.since` с тем же началом текста, нет ли незаконченного rebase или merge.
2. Сделано: допиши в `outbound` и иди дальше, не повторяя.
3. Не сделано: `pending` с действием и временем, запись, действие.
4. Перечитай результат в мире: MR с его веткой, целью и SHA головы, статус задачи, свой комментарий, удалённую ветку. Ответ команды или код 200 не доказательство: запрос мог уйти частично или лечь не туда. Совпало: запись в `outbound` с тем, что прочитано, и `pending: null`. Не совпало: действие не повторяй, `pending` оставь, вопрос пользователю с тем, что видно.

При старте сессии `pending` не пуст: сначала шаг 1. Результат найден: допиши его. Не найден и неясно, ушло ли действие: вопрос пользователю, а не повтор.

## Продолжение

Файл есть, сессия новая (упала прежняя, пользователь вызвал снова, `task-fleet` перезапустил, в том числе другим агентом):

1. Проверь файл `check-json.mjs`. Поля пройденных этапов отсутствуют: восстанови из git, код-хоста и трекера, покажи пользователю одним сообщением, запиши.
2. В корне worktree лежит `.handoff/HANDOFF.md`: прими передачу по разделу «Принять» скилла [handoff](../handoff/SKILL.md), без вопроса «подхватить ли» (его задаёт только хук на старт сессии). Расхождения передачи с файлом задачи решает файл задачи: этап, статус и внешние шаги берутся из него, из передачи только тупики, решения и следующий шаг внутри этапа.
3. `stage.status = stopped`: спроси, продолжать ли.
4. Обнови `session` своими значениями, `agentKind` и `agentSession` тоже.
5. Прерванный этап начинается заново. Правки в worktree считаются своими: покажи `git status --short` и diffstat одной строкой в чат и продолжай с них.
6. Внешние шаги проверяй по разделу выше до любого действия.
7. Worktree уже есть: у ветки нет `branch.<ветка>.base`, запиши его из `base` файла (`git config branch.<ветка>.base <база>`), задачи с 2.x пришли без него. Затем раздел «Дифф» в `SKILL.md`. Прерванный этап implement или show у задачи с интерфейсом: стенд и новая вкладка по `stand.md`.

Файл говорит `close: done`, а задачу вернули в работу: перенеси файл в `tasks/archive/<ID>-<дата>.json` и начни новый круг с этапа start.

## Передача при уходе

Сессия уходит с незаконченной задачей при стопе и при остановке по просьбе. Перед записью `blocked` или `stopped` в файл задачи она пишет передачу по разделу «Передать» скилла [handoff](../handoff/SKILL.md) в корне worktree, с `--agent` в именах handoff (`claude-code`, `codex`, `opencode`), и добивается кода 0 у `check`. Порядок важен: по записи статуса `task-fleet` может погасить сессию, и передача останется пустой заготовкой.

В передачу идёт то, чего нет в файле задачи: тупики этапа, что пробовали и почему бросили, следующий шаг внутри этапа. Этап, находки и внешние шаги уже лежат в файле, их не повторяй. Задача закрыта: передачи нет, передавать нечего.
