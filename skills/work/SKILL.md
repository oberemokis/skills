# Work

> Точка входа: [core](../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Версия: herdr 0.9.5. Оркестратор раздаёт задачи сессиям: на каждую готовит ветку и worktree, запускает агента с `task-run` в отдельном пространстве herdr и следит за состоянием по файлу задачи. Какие агенты умеют вести задачу и чем они отличаются (вид в herdr, ID сессии, продолжение, вопрос о доверии), записано в таблице `AGENTS` скрипта `scripts/launch.mjs`, и больше нигде. Пользователь видит каждую сессию пространством в herdr и отвечает ей в её панели. Код оркестратор не пишет.

Версия выше не украшение. Правила про поведение переживают мажорные обновления, а всё из раздела «Привязано к версии» перестаёт быть верным вместе с ней.

## Когда применять

- пользователь вызвал `/work` с ID задач или с промптом без задачи
- вызов без аргументов: после перезапуска herdr, перезагрузки или новой панели оркестратора поднять надзор над сессиями, запущенными раньше
- нужно перезапустить или закрыть сессии задач

## Когда НЕ применять

- одна задача в текущей сессии: это `task-run` напрямую
- поиск или ревью внутри своей сессии: встроенный субагент дешевле, ему не нужны ни worktree, ни пространство
- оркестратор не в панели herdr: `node <папка скилла>/../task-run/scripts/host.mjs` ответил не `herdr`. Скажи «запусти оркестратор в панели herdr» и остановись

## Правила

### Вызов

`/work <ID>[=минуты] [<ID>[=минуты] ...] [--level S|M|L] [--agent <вид>]`, `/work "<промпт>"` для работы без задачи, без аргументов для восстановления, `--setup` для опросника. Например, `/work PROJ-1=25 PROJ-2`: первая задача с ручной оценкой 25 минут, вторая с оценкой из трекера либо через оценщик. Отдели минуты от ID до проверки `taskId`; принимай только целые положительные минуты. Скрипты и описания `task-run` лежат рядом: `<папка скилла>/../task-run/`. Команды herdr описывает `herdr --help` и `herdr <группа> <команда> --help`.

### Проект

Вызов принимает `--project <имя>` в том числе при восстановлении. Передай его в `node <папка скилла>/../task-run/scripts/resolve-project.mjs`; без имени остаётся поиск по текущему checkout. `missing`, `broken` или `--setup`: опросник по `../task-run/project.md`, задачи ждут его конца. Затем проверь подключения из `tracker.check` и `codeHost.check`. Ошибка SSH не запускает опросник заново.

При `execution.mode=ssh` сначала прочитай [удалённый маршрут](../task-run/remote.md). Он определяет место исполнения всех следующих шагов, включая проверку веток, подготовку worktree, восстановление и уборку. Отсутствие локального клона нормально. Не запускай подготовку из локального терминала напрямую.

Один запуск работает с одним разрешённым профилем. ID чужого формата (`taskId` не совпал) не бери, назови.

### Агент задачи

Флаг `--agent` вызова, иначе поле `agent` в `project.json`, иначе `claude`. Агента нет в таблице `AGENTS`: `launch.mjs` ответит кодом 2 со списком известных, назови его пользователю и не подменяй своим.

### Предел

Живых сессий задач на машине не больше трёх, считая чужие оркестраторы и всех агентов вместе. Живая сессия это панель herdr с агентом (поле `agent` в `herdr api snapshot`), если у панели метка `work=1` или её `foreground_cwd` внутри `worktree.dir` любого проекта из `~/.local/state/task-run/*/project.json`. Агента в панели herdr видит сам: и на вопросе о доверии папке, и после Ctrl+Z. `cwd` панели не годится: это папка запуска.

Места считает `scripts/launch.mjs` из «Запуска» под локом `~/.local/state/task-run/work.lock` и держит лок, пока в новой панели не появится агент: иначе второй оркестратор его не посчитает.

Места нет (код 4): вопрос «Сверх предела» по каждой лишней задаче. «Отложить» (рекомендую): не запускать, сказать, как вызвать позже. «Ждать места»: запустить, когда закроется сессия. Сессия занимает место, пока жива, в любом состоянии, в том числе пока ждёт ответа продукта.

### Подготовка задачи

До worktree, потому что от этого зависит база:

1. Глаголы трекера из `rules.md`: «прочитать задачу» и «задача готова к работе и твоя». Не готова: задачу не берёшь, причину пишешь в чат.
2. База и способ доставки по разделу «База», с проверкой существующей ветки локально и на origin.
3. Worktree по шагам 1–7 раздела «Без `--work`» в `../task-run/stages/worktree.md`, без входа в него. Путь `<root>/<worktree.dir>/<ветка с - вместо />`.
4. У задачи уже есть живая сессия Claude, запущенная руками вне `work`, если в `~/.claude/sessions/*.json` есть живой `pid` с `sessionId`, равным `session.agentSession` файла задачи (у старых файлов `session.claudeSession`), а `session.agentKind` равен `claude` или его нет. Тогда вторую не запускай, назови её панель. Панель с меткой `task=<ID>` проверяет `launch.mjs` (код 5).

### Выбор входа для каждой задачи

- Пользователь дал время: обычный `task-run`, добавь к `--task-args` параметры `--minutes N --source user`. Иначе есть оценка в поле трекера по правилам проекта: то же, `--source tracker`; дни переводи по рабочему календарю трекера. Неизвестная единица или недоступное поле не равны пустой оценке: уточни.
- Поле пусто и ручной оценки нет: добавь к `launch.mjs` ключ `--estimate-first`. В той же сессии стартует [task-estimate](../task-estimate/SKILL.md), после плана он передаёт задачу `task-run`. `--level` не содержит минут и не пропускает оценщик. В трекер прогноз не записывай.
- Перезапуск: готовая `estimate` или задача уже дошла до implement и далее (в том числе старый формат) → `task-run` по состоянию. До плана без сохранённой оценки снова применяй выбор входа; при `--resume` оставь обычный «продолжай». Для промпта без задачи этот выбор не нужен.

### Запуск

Имя сессии это ветка в нижнем регистре с `-` вместо `/`, до 32 знаков `[a-z0-9_-]`, первой идёт буква: ветку с цифры предвари `w-`. Под этим именем herdr знает агента, а пространство называется `work-<имя>`. ID новой сессии выдаёт скрипт, если агент позволяет задать его заранее (Claude позволяет), и возвращает в `session`, поэтому перезапуск известен с первой секунды.

Скиллы стоят ссылками в папках скиллов агентов, и каждая сессия, в том числе перезапущенная, видит их сама.

1. Одной командой, не фоном и с таймаутом инструмента не меньше 120 секунд (скрипт укладывается в `--budget`, 90 секунд):

   ```sh
   flock -w 20 -E 75 ~/.local/state/task-run/work.lock \
     node <папка скилла>/scripts/launch.mjs --project <проект> --branch <ветка> --name <имя> --cwd <worktree> --task <ID> --agent <вид> [--estimate-first] \
     --task-args '<ID> --work --base <база> --branch <ветка> --worktree <путь> [--level X] [--minutes N --source user|tracker]'
   ```

   Промпт `task-run` в синтаксисе агента собирает скрипт из `--task-args`: синтаксисы вызова скилла у агентов разные, и знать их оркестратору не нужно. Аргументы в одинарных кавычках. Скрипт проверяет панель задачи и места, открывает пространство без фокуса (окно пользователя остаётся где было), ставит панели метки `work=1`, `task`, `agent`, `agent-session` и `project` и запускает агента командой `herdr agent start`: herdr набирает её в оболочке панели и ждёт, пока агент примет ввод.

   Модель и режим разрешений не передавай: сессия берёт настройки пользователя. Промпт идёт аргументом запуска, а не отдельным сообщением: так он доходит и до агента, который ещё стоит на вопросе о доверии.
2. Ответ скрипта это JSON одной строкой, смысл по коду выхода:
   - 0, `started`: агент `agent` под именем `name` в панели `pane` пространства `workspace`, его сессия `session` (`null`, если ID агент выдаёт сам); `ready: true` значит агент принял ввод, `trust: true` значит он спрашивает, доверять ли папке worktree;
   - 4, `full`: мест нет, занятые в `live`;
   - 5, `exists`: у задачи уже есть панель; `alive: false` значит агент из неё вышел, дальше «Пропала сессия» (там `--replace`);
   - 6, `no-agent`: агент не стал готов за таймаут (`reason: timeout`) или вышел сразу (`reason: exited`: команды нет, сломан конфиг), его процесс скрипт погасил, оболочка осталась. Прочитай экран `herdr pane read <панель> --source recent --lines 40` и задай вопрос «<ID>: <агент> не запустился» с экраном в описании: «Запустить другим агентом» (`--replace --agent <другой>`) или «Отложить» (строка в чат, как убрать пространство: «Уборка»);
   - 75 от `flock`: лок держит кто-то другой, назови его по `lsof`;
   - 1 и 2: ошибка herdr или вызова, текст в JSON или в stderr.
3. `trust: true`: не отвечай за пользователя, строка в чат «<ID> ждёт тебя: доверить папку worktree, пространство work-<имя>». Надзор увидит перемену, когда агент примет промпт. `ready: false` без `trust`: прочитай экран и покажи пользователю.

### Надзор

Сессии не дети оркестратора, надзор идёт по меткам. Пока есть живые сессии, держи одну фоновую команду `node <папка скилла>/scripts/watch.mjs ~/.local/state/task-run/work-watch-$HERDR_PANE_ID.json`. Она подписывается на события herdr, выходит только на перемене (статус, ход, агент в панели и его остановка, конец панели) и печатает изменившиеся сессии с `pane`, `task`, `agent` (вид), `status`, `alive` (агент в панели) и `stopped` (агент остановлен по Ctrl+Z). По выходу прочитай из `tasks/<ID>.json` только `stage` и запусти её снова. Код 3: сервер herdr закрыл соединение, пройди восстановление.

- Файла задачи ещё нет: сессия на этапе start, ничего не делай.
- Сессия на чтение (`task=read-…`): файла у неё не бывает. Конец хода: строка «<имя> ответила, пространство work-<имя>»; вопрос: «<имя> ждёт тебя»; агент пропал: строка «<имя> завершилась», перезапуск не предлагай, такую сессию дешевле поднять заново.
- `stage.waiting` сменился: одна строка в чат, «<ID> ждёт тебя: <waiting>, пространство work-<имя>». Пространство с вопросом herdr подсвечивает сам, дублировать уведомлением не надо.
- `stage.status` стал `blocked`: строка в чат «<ID> заблокирована на этапе <этап>: <причина из `note` этапа>, пространство work-<имя>». Сессию не гаси: ответ пользователя в её панели может снять блок.
- `stage.status` стал `stopped`: сессия уже оставила передачу и остановилась по просьбе, погаси агента так же, как после закрытия, и строка в чат «<ID> остановлена на этапе <этап>».
- `close` закрыт: `node <папка скилла>/scripts/stop.mjs <панель>`. Скрипт находит процесс агента под оболочкой панели и шлёт ему TERM и CONT, а агенту, который не вышел (остановленный по Ctrl+Z в fish так и остаётся), KILL. Оболочка в пространстве остаётся, место освобождается. Код 1 и `alive`: агент не вышел, покажи экран пользователю. `herdr pane close` и `herdr workspace close` для этого не годятся: они закрывают пространство, а оно нужно пользователю до уборки.
- `stopped: true`: агента остановили по Ctrl+Z, сессия жива. Строка в чат «<ID> остановлена в панели, пространство work-<имя>», перезапуск не предлагай.
- Статус `idle` без смены этапа и без ожидания: прочитай экран. При ошибке API модели допустимо `herdr agent prompt <имя> "продолжай"`. Обрыв SSH или неясное происхождение ошибки: не отправляй «продолжай», сначала установи результат последней операции.

«Готово» определяется по файлу, а не по `idle` или `done`: сессия, которая ждёт пайплайн фоновой командой, тоже стоит в `idle`. Этап задачи пользователь видит только по строкам в чате, поэтому строку «ждёт тебя» пиши всегда.

### Пропала сессия

Панели с меткой `task=<ID>` нет, `state` у неё `gone`, или агента в ней нет: `alive: false` в выводе надзора. Остановленный агент (`stopped: true`) не пропал. Прочитай `stage` из файла:

- `stopped`, `done` или `blocked`: так и задумано, ничего не делай. Строку про блок надзор уже написал;
- иначе сразу глагол «приостановил» и строка в чат: иначе флаг «в работе» копит время, пока вопрос ждёт. Это единственное действие оркестратора в трекере. Затем вопрос «Сессия <ID> завершилась на этапе <этап>»: «Перезапустить с этапа», «Перезапустить другим агентом» (только если в таблице `AGENTS` их больше одного) или «Оставить остановленной». Автоматически не перезапускай: Ctrl+C пользователя от падения не отличить.

Перезапуск: `launch.mjs` по разделу «Запуск» с флагом `--replace`. В панели задачи, где осталась оболочка, скрипт запустит агента заново; панели нет (herdr перезапускался), он откроет пространство заново. Панель, где агент ещё жив, скрипт не тронет и ответит кодом 5. Команду агента в оставшуюся оболочку сам не набирай: места и метки тогда никто не проверит.

- тот же агент и его сессия на месте (у Claude файл `~/.claude/projects/*/<id>.jsonl`, `id` из `session.agentSession` или старого `session.claudeSession`): `--agent <вид> --session <id> --resume -- 'продолжай'`;
- другой агент или сессии нет: `--agent <вид> --task-args …` без `--session`, с прежними аргументами `task-run`. Новая сессия продолжит по файлу задачи, git и передаче handoff, если её оставила прежняя.

### Восстановление

Вызов без аргументов и код 3 надзора: пройди по задачам проекта с `work: true`, у которых этап не `done` и не `stopped`. Живая сессия есть: под надзор. Нет: раздел «Пропала сессия», а заблокированные без сессии назови одной строкой с этапом и причиной.

Оркестратор, поднятый в новой панели, видит сессии старого по меткам. Файл снимка надзора у него свой, поэтому первая же проверка покажет все живые сессии как перемену: прочитай их этапы и продолжай.

### Промпт без задачи

Маршрут только для локального Claude: в SSH и OpenCode не создавай detached worktree, предложи задачу с ID. Ограничения read-only Claude не распространяются на команды SSH.

Вопрос «Нужны правки в коде?».

- «Да»: правки идут только через задачу, предложи завести её в трекере и вызвать `/work` с её ID.
- «Нет, только чтение»: `git worktree add --detach <root>/<worktree.dir>/read-<имя> origin/<база>`, `launch.mjs` по разделу «Запуск» с `--task read-<имя>`, а после `--` вместо промпта `task-run` идут `--permission-mode plan --disallowedTools=Edit,Write,NotebookEdit,mcp__lean-ctx__ctx_patch,mcp__lean-ctx__ctx_call` и промпт пользователя как есть. Форма с `=` обязательна: без неё промпт уйдёт в список запрещённых инструментов. `ctx_patch` пишет в файлы мимо `Edit`, а `ctx_call` доходит до него по имени, поэтому запрещены оба. Одного режима plan мало: его снимают, а основная папка может быть смонтирована в стенд. Такая сессия тоже занимает место.

### Ответы и уборка

- Ответ сессии читай коротко: `herdr pane read <панель> --source recent --lines 60`. Длинный не помещается: попроси сессию записать его в файл вне worktree и прочитай файл.
- Из JSON herdr бери только нужные поля, `context` из файлов задач в свой контекст не грузи.
- Уборка только по просьбе: `git status --porcelain` в worktree, грязно: спроси, `--force` сам не добавляй. Затем `git -C <root> worktree remove <путь>` и `herdr workspace close <пространство>`. Ветка остаётся.
- Чужие пространства и панели не закрывай. Пространство репозитория тоже: вместе с ним herdr закроет все пространства задач в его группе.

## Привязано к версии

herdr 0.9.5; остальное в `herdr --help`:

- `herdr api snapshot` одним вызовом отдаёт панели, агентов и пространства; у панели `agent` (вид, без агента поля нет), `agent_status` (`idle`, `working`, `blocked`, `done`, `unknown`), `cwd` (папка запуска), `foreground_cwd` и `tokens`;
- метки панели ставит `herdr pane report-metadata <панель> --source work --token K=V`, они сливаются по ключу и переживают выход агента;
- worktree открывает `herdr worktree open --path <worktree> --workspace <пространство репозитория>` (или `--cwd <корень>`, тогда пространство репозитория herdr заводит сам), и в боковой панели он стоит веткой под репозиторием. Пространство репозитория `launch.mjs` ищет в снимке: с `worktree.is_linked_worktree: false` и тем же `repo_root`, иначе обычное с панелью в корне. Закрытие пространства репозитория закрывает всю группу вместе с сессиями задач. Worktree, уже открытый в другом пространстве, и папку управления SSH скрипт открывает отдельным пространством через `herdr workspace create`: `worktree open` по открытому переименовал бы чужое пространство;
- `herdr agent start <имя> --kind <вид> --pane <панель> -- <аргументы>` набирает команду агента в оболочке панели с правильными кавычками и ждёт готовности; на вопросе о доверии отвечает ошибкой `agent_not_ready`, а агент в панели остаётся в статусе `blocked`; агент, вышедший сразу, даёт `timeout` по истечении таймаута, и агента в панели нет;
- имя агента `[a-z][a-z0-9_-]{0,31}`, уникально среди живых агентов и освобождается, когда агент выходит;
- после Ctrl+Z агент остаётся в панели со статусом `blocked`, процесс в состоянии `T`; в fish TERM и CONT такой процесс не гасят, нужен KILL;
- `herdr pane process-info --pane <панель>` даёт `shell_pid` оболочки панели, от неё `stop.mjs` ищет агента вниз по дереву (`ps -o pid=,ppid=,stat=,args=`); у Claude имя процесса равно номеру версии, программа видна по `argv`;
- события идут подпиской `events.subscribe` в сокет `$HERDR_SOCKET_PATH`, отдельной команды CLI у неё нет;
- `herdr pane read` отдаёт текст экрана, а не JSON; остальные команды отвечают JSON, ошибки JSON в stderr с кодом 1.

lean-ctx 3.12.5: хук Bash и `ctx_shell` пропускают только команды из списка и не пропускают встроенный код (`sh -c`, `node -e`, `eval`). `herdr`, `flock` и `claude` пользователь разрешает сам командой `lean-ctx allow <команда>`. Ответ `[BLOCKED]` на одну из них: остановись и назови команду, в обход через скрипт не иди.

Claude Code 2.1.332: промпт аргументом со слэш-командой запускает скилл и с `disable-model-invocation`; `--session-id` задаёт ID новой сессии, `--resume` поднимает её по ID.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| `herdr workspace close` по закрытой задаче | `scripts/stop.mjs <панель>` | пространство нужно пользователю до уборки |
| промпт `task-run` отдельным сообщением через `herdr agent prompt` | `--task-args` у `launch.mjs` | агент на вопросе о доверии промпт не примет |
| промпт `task-run` своими руками в синтаксисе агента | `--task-args` | у агентов разный синтаксис вызова скилла, `$` в двойных кавычках съедает оболочка |
| считать агента по процессам переднего плана | поле `agent` панели в herdr | после Ctrl+Z агент уходит с переднего плана, и живая сессия выглядит пропавшей |
| `--disallowedTools Edit Write …` перед промптом | `--disallowedTools=…` | промпт уходит в список инструментов |
| ответить на вопрос о доверии за пользователя | назвать пространство | папку доверяет человек |
| перезапуск пропавшей сессии без вопроса | вопрос, «приостановил» сразу | пользователь мог остановить её сам, повтор доставки опасен |
| «готово» по `idle` | `stage` из файла задачи | `idle` и при ожидании пайплайна |
| `herdr agent start` своей командой | `scripts/launch.mjs` под `flock` | места без лока считаются наперегонки, метки не ставятся |
| набрать команду агента в оставшуюся оболочку через `herdr pane send-text` | `launch.mjs --replace` | ни места, ни метки, ни ID сессии никто не проверит |
