# Handoff

> Точка входа: [core](../core/SKILL.md). Если core ещё не прочитан, прочитать его до этого скилла.

Передача это файл, по которому агент без памяти о прошлой сессии продолжает работу с того места, где её бросили. Другой агент не видит ни переписки, ни прочитанных файлов, ни того, что уже пробовали. Всё, что не записано, он будет выяснять заново или сделает иначе.

Механику ведёт скрипт `<папка скилла>/scripts/handoff.mjs`: заготовка со снимком git, проверка заполнения, сводка расхождений для принимающего, хук на старт сессии. Текст пишет агент.

## Когда применять

- пользователь переходит в другой агент или новую сессию, а задача не закончена
- контекст подходит к пределу, и сжатие съест подробности
- пользователь просит передать, сохранить состояние или подхватить прошлую работу
- в корне рабочей копии лежит `.handoff/HANDOFF.md`, или хук сообщил о передаче

## Когда НЕ применять

- задача закончена: передавать нечего, итог говорится пользователю
- долгая память о проекте (стенд, соглашения, ловушки): это память агента или документация, передача живёт до приёма
- описание PR или сообщение коммита: передача локальная и в git не идёт

## Правила

### Передать

1. Запусти `node <папка скилла>/scripts/handoff.mjs prepare --agent <имя>`, где имя это `claude-code`, `codex`, `opencode` или имя твоего агента. Скрипт пишет заготовку `.handoff/HANDOFF.md` в корне рабочей копии и прячет папку от git собственным `.gitignore`. Прежняя заполненная передача уходит в `.handoff/history`.
2. Прочитай заготовку и заполни разделы встроенной правкой агента. Фронтматтер и раздел «Снимок репозитория» не трогай: по ним принимающий считает расхождения.
3. Запусти `check`. Код 1 значит пропуски, их скрипт перечисляет. Добивайся кода 0.
4. Скажи пользователю путь к файлу и одной строкой, с чего начнёт принимающий.

У каждого worktree своя передача: она лежит в его корне, и из основной папки её не видно. Принимающий должен открыть тот же worktree.

### Что писать в разделы

Пиши для агента, который не видел сессии. «Как обсуждали», «тот файл», «вариант два» ему ничего не скажут. Нужны пути от корня, имена функций и команды целиком.

Каждый факт с доказательством. «Тесты проходят» превращается в команду и результат: какой прогон, сколько тестов, когда. Непроверенное помечай словом «не проверено», иначе принимающий будет на него опираться.

Решения пиши вместе с причиной и тем, кто решил. То, что утвердил пользователь, принимающий не пересматривает без него. Решение без причины следующий агент отменит при первом неудобстве.

Тупики самый дорогой раздел. Отвергнутый подход без записи принимающий попробует снова и потеряет то же время. Пиши, что пробовали, на чём сломалось и почему не стоит повторять.

Следующий шаг это одно действие, а не план: файл и что в нём сделать, команда, вопрос пользователю. План целиком лежит в задаче или в разделе «В процессе».

Ссылайся на файлы, а не копируй их. Дифф, список незакоммиченного и последние коммиты уже в снимке. Логи вставляй только той строкой, где ошибка.

Пустой раздел заполняй словом «нет», а не удаляй: `check` проверяет, что каждый раздел рассмотрен. Секретов, токенов и содержимого `.env` в передаче не бывает.

Ориентир объёма: до восьмидесяти строк своего текста. Длиннее, значит пересказываешь сессию, а не передаёшь состояние.

### Принять

1. Запусти `node <папка скилла>/scripts/handoff.mjs status`. Он говорит, кто и когда передал, и что изменилось с тех пор: коммиты после передачи, смена ветки, переписанная история, незакоммиченные файлы сейчас.
2. Прочитай `.handoff/HANDOFF.md` целиком.
3. Выполни команды из «Как проверить». Состояние разошлось с описанным: красные тесты, коммиты после передачи, другая ветка. Тогда назови расхождение пользователю до работы, а не чини молча.
4. Скажи пользователю в две-три строки: от кого передача, какая задача, какой следующий шаг, что разошлось. Открытые вопросы задай сразу, до первой правки.
5. Закрой передачу: `close`. Файл уходит в `.handoff/history`, и следующая сессия не получит устаревшую передачу как живую.

В сессии задачи `task-run` передача принимается без вопроса «подхватить ли»: её прямо ждёт перезапуск задачи. Там же расхождения передачи с файлом задачи решает файл задачи (раздел «Продолжение» его `state.md`).

`status` с кодом 1 значит заготовку не дописали: передающая сессия оборвалась. Используй заполненные разделы и снимок, а пользователю скажи, что передача неполная.

Передача старше пары дней или с переписанной историей описывает чужое состояние. Сверь её с git и спроси пользователя, актуальна ли задача, прежде чем идти по «Следующему шагу».

### Хук на старт сессии

Claude Code сам сообщает о передаче, если повесить `hook` на событие `SessionStart` в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear",
        "hooks": [{ "type": "command", "command": "node ~/.claude/skills/handoff/scripts/handoff.mjs hook" }]
      }
    ]
  }
}
```

Без передачи хук молчит. С передачей он добавляет в контекст сводку `status` и просит спросить пользователя, подхватить ли её. Любая ошибка внутри хука гасится, старт сессии он не роняет.

Другие агенты хуком не подключены: там пользователь говорит «подхвати передачу», и скилл подтягивается по описанию.

## Антипаттерны

| Не так | Так | Почему |
| --- | --- | --- |
| пересказ сессии по порядку | состояние по разделам | принимающему нужно, где мы, а не как сюда шли |
| «тесты проходят» без команды | команда, результат, время | непроверяемое утверждение принимают на веру |
| передача без тупиков | что пробовали и почему бросили | принимающий повторит тот же путь |
| `.handoff` в `.gitignore` проекта | `.gitignore` внутри `.handoff` от скрипта | общий файл коммитит пользователь |
| передача в `.git` | `.handoff` в корне рабочей копии | песочница Codex держит `.git` только на чтение |
| работа по передаче без `status` | сначала сводка расхождений | после передачи могли коммитить, переключать ветку, переписывать историю |
| принятая передача остаётся в корне | `close` после приёма | хук будет предлагать её каждой новой сессии |
