# Проверка на истории

Выгрузка за 12–19 ноября 2026: фильтр по полю «Разработчик», сортировка по приоритету и затем по обновлению, оба по убыванию. Среди 104 строк за период взяты только задачи, для которых одновременно нашлись: локальный `close: done` в `task-run`, карта правки, случаи плана, положительные «Оценка» и «Затраченное время» в трекере. Получилось 19 пар. Одна лишь фамилия разработчика не подтверждает работу агента. Статус в трекере не служил признаком окончания: некоторые сессии завершились сдачей локального коммита.

В [replay.json](replay.json) только четыре числа на задачу: уникальные пути карты, случаи, оценка трекера и списанные минуты. Порядок по моменту закрытия локальной сессии. Старые карты и случаи прочитаны из финальных файлов: могли уточняться в ходе работы. Списание трекера подтверждает учтённое время задачи с агентской сессией, но не доказывает отсутствие ручной работы. Это ретроспектива одного проекта, не замер чистого времени модели.

Из каталога скилла:

```sh
node scripts/estimate.mjs simulate replay.json 13
node scripts/estimate.mjs plan 4 7
node scripts/estimate.mjs manual 60
```

Первые 13 строк: минимизация суммы абсолютных ошибок, поиск целых `base` от 5 до 30 минут и обоих весов от 0 до 12. Пользовательская конфигурация тоже участвует как кандидат; при равной ошибке сохраняется первый вариант. На последних 6 строках веса не меняются. Для сравнения взяты медиана факта обучения (16 минут) и медиана `факт / трекер` обучения (1/3).

| Прогноз на контрольных 6 | MAE, мин | Среднее смещение, мин | Худшая ошибка, мин |
|---|---:|---:|---:|
| Оценка трекера | 46,83 | +46,83 | 128 |
| Оценка трекера × 1/3 | 22,17 | −16,50 | 55 |
| Всегда 16 минут | 32,17 | −32,17 | 79 |
| План: `5 + (F − 1) + 3C` | 18,83 | −14,83 | 64 |

Проверка чувствительности того же профиля к границе выборки: на разбиении 10/9 MAE формулы 16,00 минуты против 43,78 у трекера; на 15/4 результат 23,00 против 50,75. Повтор: замени `13` в команде на `10` или `15`. Это перекрывающиеся части одной истории, а не три независимых эксперимента.

Например, на плане из 6 файлов и 7 случаев прогноз 31 минута, факт 95. По двум счётчикам нельзя увидеть всю сложность. Множитель 1/3 нужен для сравнения, не для сокращения ручных оценок. В выборке нет факта более двух часов: границы T4/T5 служат для очереди, точность на крупных задачах ещё не измерена.

Для своей выгрузки передай JSON-массив того же формата в порядке закрытия от старых к новым; `tracker` можно опустить. У задач нового формата CLI читает непосредственно каталог `tasks`, берёт зафиксированные до реализации входы и только законченные сессии с подтверждённым фактом. Не смешивай разные проекты, незавершённые прогоны и время ожидания с активным. При подборе на новой истории сохрани новые задачи для проверки: результат подбора на собственной обучающей части точности не показывает.
