# Калибровка скиллов

Скиллы это инструкции для агента, и без измерения неизвестно, находит ли агент то, что должен находить, и не шумит ли. Эта папка хранит фикстуры с посеянными дефектами и эталонные списки. Скиллы здесь не запускаются и в маршрутизацию не попадают: это инструмент разработки репозитория, а не часть плагина.

## Что есть

Фикстура `test-review/fixture/` содержит маленький набор тестов с пятью посеянными дефектами. Каждый дефект привязан к пункту чеклиста скилла `test/test-review` и к уровню порядка починки. Эталон лежит в `test-review/expected.json`. Один тест в фикстуре чистый, его строка в эталоне не указана, поэтому любая находка на нём считается лишней.

`score.mjs` сравнивает список находок с эталоном. Находка совпадает с дефектом, если файл тот же и номер строки отличается не больше чем на две строки. Уровень считается отдельно.

## Как проверить набор

Без аргументов скрипт печатает строки эталона из фикстуры и прогоняет эталон сам на себя. Recall и precision должны быть 100%, иначе фикстура или эталон разошлись.

```
pnpm eval
```

## Как измерить скилл

Откройте сессию Claude Code в корне репозитория. Попросите агента проверить тесты в `evals/test-review/fixture` по скиллу `test/test-review` и вернуть находки JSON-массивом вида `[{"file": "cart.test.ts", "line": 7, "item": 5, "level": 1}]`. Сохраните ответ в `evals/test-review/out/findings.json`, затем запустите:

```
pnpm eval evals/test-review/out/findings.json
```

Папка `out/` не коммитится. Результаты разных прогонов сравнивайте по recall, precision и уровню, а не по одному запуску: модель недетерминирована, и один прогон даёт шум.

## Что добавлять

Новый набор кладётся в `evals/<скилл>/` с фикстурой, `expected.json` и строками эталона. Скрипт сейчас знает только `test-review`: чтобы подключить новый скилл, допишите его имя в список `suites` в `score.mjs`.
