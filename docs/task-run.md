# task-run и task-fleet: запись решения

Ноябрь 2026. Скиллы заменяют личную очередь задач, которая вела до пяти задач по одной в одной сессии и была завязана на один проект. С версии 3.0.0 fleet работает в Herdr (ядро hc и приложение) вместо старого herdr.

## Что решили

- Одна задача, одна сессия Claude, один worktree, одно пространство Herdr. Очереди нет: параллельность даёт `task-fleet`, маршрут одной задачи ведёт `task-run`.
- Ядро в этом репозитории, всё про проект у пользователя: `~/.local/state/task-run/<проект>/` с `project.json` (данные, схема), `rules.md` (правила прозой и глаголы трекера и код-хоста) и `tasks/<ID>.json` (состояние задачи). Ядро говорит глаголами («начал работу», «открыть MR») и не знает ни трекера, ни код-хоста.
- Проект узнаётся по нормализованному `origin`, корень это родитель общего `.git`. Основная папка и все worktree дают один проект.
- Первый вызов в проекте запускает опросник: он сам выясняет то, что видно в репозитории, трекере и код-хосте, спрашивает остальное и записывает после подтверждения. Снова он запускается только по `--setup` и когда данные или подключения сломаны. Токены через чат не проходят.
- Worktree лежат в `.worktrees/<ветка>` корня проекта. Создаёт их git с `--no-track`. База определяется до создания worktree и записывается ветке в `branch.<ветка>.base`.
- Этапы лежат справочниками внутри `task-run`: в списке скиллов два описания вместо девяти.
- Fleet работает только в Herdr. Оркестратор узнаёт его по предкам процесса (`host.mjs`), а не по переменным окружения: `HERDR_*` и `HC_*` наследуются в обе стороны.
- Сессия задачи запускается `hc run --no-parent` с метками `task-fleet=1`, `task=<ID>` и `claude-session=<uuid>`, в новом пространстве со своим id. Claude идёт внутри оболочки: закрытие задачи (`kill -TERM` процесса Claude) и `/exit` оставляют пространство с оболочкой. ID сессии Claude задаёт оркестратор (`--session-id`), поэтому перезапуск известен с первой секунды.
- Запуск сессии и старт стенда идут скриптами `task-fleet/scripts/launch.mjs` и `task-run/scripts/stand.mjs`, а не командой оболочки со встроенным кодом: хук lean-ctx встроенный код (`sh -c`) не пропускает. `launch.mjs` под `flock` считает места, ловит дубль задачи, ждёт Claude и отвечает кодом: 0 запущено, 4 мест нет, 5 задача уже идёт, 6 Claude не поднялся.
- Надзор по меткам, а не по родству: `watch.mjs` ждёт `hc events`, сравнивает снимки статусов и будит оркестратора только на перемене. Новый оркестратор видит сессии старого, закрытие его терминала сессии не убивает.
- Порядок ревью: агенты (M и L), затем дифф и показ в браузере одной остановкой перед коммитом. Замечание повторяет шаг целиком, поэтому в коммит уходит просмотренный дифф.
- Дифф в Herdr показывает панель Review раскладки workbench из herdr-app: она следит за worktree терминала в фокусе, базу берёт из `branch.<ветка>.base`, а новое пространство открывается с ней. Замечания можно прислать из неё: в вопросе показа есть вариант «Замечания пришлю из Review», после него сессия ждёт без диалога, потому что агенту с открытым вопросом Review не пишет. Вне Herdr сессия даёт команду gitone.
- Смотреть работу можно с начала, а не только на показе. У задачи с интерфейсом стенд и вкладка поднимаются перед первой правкой интерфейса и живут до одобрения показа. Вкладку ведёт расширение Claude in Chrome, поэтому пользователь видит и правки, и клики сценариев. Страницы для вкладки задача хранит в `context.pages`.
- Порт стенда один на машину. Занят чужой задачей на реализации: сессия работает без вкладки и не спрашивает, на показе вопрос остаётся.
- Файл задачи пишет только её сессия и только через `check-json.mjs --commit`. Внешние шаги идемпотентны: сверка с миром, намерение до действия, факт после. Правота: git и код-хост, затем трекер, файл последним.
- Флаг «в работе» снимается, пока сессия ждёт человека: иначе три ждущие сессии копят тройное время. Своих уведомлений нет: Herdr сам звонит на вопросе и конце хода.
- До трёх живых сессий на машину: терминалы с Claude на переднем плане, с меткой fleet или внутри папок worktree, под `flock -w 20`. Сверх предела вопрос «отложить или ждать».
- Этапы всех задач были видны в панели «Задачи fleet» в сессии оркестратора, модуле хуков плагина (`hooks/fleet-panel`). С выходом из плагина панель удалена (последняя версия под тегом `v3.1.0`), и этап задачи виден только по строкам сессий в чате.
- Пропавшую сессию оркестратор сразу приостанавливает в трекере, а перезапускает только после вопроса: `launch.mjs --replace` с прежним ID сессии и `--resume`, а если файла сессии нет, новая сессия с промптом `task-run`. После краха ядра или перезагрузки `/task-fleet` без аргументов проходит по задачам и делает то же.
- Промпт без задачи идёт только на чтение: detached worktree, режим plan, запрет Edit и Write. Правки только через задачу.
- Красный пайплайн своей ветки: amend и `--force-with-lease` после backup-ветки, чтобы держать один коммит на ветку. В общие ветки force-push запрещён.

## Что отвергли и почему

| Вариант | Причина отказа |
| --- | --- |
| встроенные субагенты с изоляцией в worktree | живут внутри оркестратора, в Herdr их не видно и в их сессию не зайти |
| ветка от `origin/<база>` с upstream | первый `git push` уходит в базу |
| worktree до выбора базы | ветка от не той базы, а пересоздать worktree изнутри своей сессии нельзя |
| два оркестратора (общий `fleet` и тонкий `task-fleet`) | второй слой почти ничего не добавлял, а описание висит в контексте |
| этапы отдельными скиллами | девять описаний в каждой сессии ради того, что вызывается только из маршрута |
| адаптер проекта markdown-скиллом | висел бы в списке скиллов во всех проектах |
| папка проекта в репозитории | командный репозиторий не трогаем |
| знание YouTrack и GitLab справочниками в ядре | без второго проекта граница «инструмент вообще» и «инструмент этого проекта» угадана |
| список запрещённых идентификаторов в `scripts/check.sh` | сам опубликовал бы то, что прячем; проверка идёт по формам |
| счётчик мест в `fleet.json` | не знает о перезапусках и чужих оркестраторах, после падений врёт |
| автоматический перезапуск пропавшей сессии | Ctrl+C пользователя от падения не отличить, повтор доставки опасен |
| только режим plan для промпта без задачи | режим снимается, а основная папка бывает смонтирована в стенд |
| дифф и показ двумя остановками | правка после показа уходила в коммит непросмотренной |
| JSON-схема через ajv | зависимость ради подмножества, которого хватает своему валидатору |
| дифф и стенд только на показе | пользователь видел работу, когда переделка уже стоила круга исправлений |
| свой порт стенда на сессию | на других портах стенд проекта работает не целиком |
| вопрос про занятый порт на реализации | останавливает реализацию, а порт освобождается сам |
| вкладка командой `open` в браузере пользователя | видно правки, но не клики сценариев; остаётся запасным путём без расширения |
| fleet сразу для старого herdr и Herdr | два справочника команд и две живые проверки на каждую правку; откат на 2.x дешевле |
| gitone в Herdr | панель Review показывает тот же дифф и пересылает замечания агенту |
| надзор через `hc wait --children` | новый оркестратор не видит детей старого, а ребёнок без `--no-parent` живёт без своей панели и умирает с родителем |
| `hc kill` при закрытии задачи | закрывает панель и пространство вместе с Claude |
| `hc send` с промптом `task-run` | агенту текст приходит в обёртке, слэш-команда в ней не срабатывает |
| своё уведомление модом Herdr | связало бы публичную раскладку с task-run, а что ждёт задача, видно в панели |
| панель задач в сессиях задач | рядом терминал и панель Review, ширины не хватает, а свой этап сессия и так пишет в чат |
| отдельный мод вне плагина | загружается только в той сессии, где его написали, оркестратор его не видит |

## Границы

- Проверено на одном проекте: граница ядра держится проверкой по формам, а не вторым проектом.
- Только агенты Claude, только один проект на запуск оркестратора.
- Нужен Herdr с раскладкой workbench из [herdr-app](https://github.com/oberemokis/herdr-app): без неё нет панели Review, и сессия даёт команду gitone.
- Показ задач с бэкендом на общем стенде не видит правок worktree, если стенд смонтирован из основной папки; такие задачи проверяются автотестами worktree.
- Плановой перепроверки папки проекта нет.
- Лок мест и порта стенда берётся через `flock`: в macOS его нет из коробки, нужен пакет из Homebrew.
- Вкладкой стенда за раз владеет одна задача: расширение Claude in Chrome общее на сессии, но порт держит одна.
- Стенд, переживший свою сессию, держит лок порта от имени закрытой задачи, и следующая задача на показе ждёт его. Так было и в старом herdr, исправление отложено.

## Выход из плагина

16 ноября 2026 репозиторий перестал быть плагином Claude Code: скиллы лежат плоско в `skills/<имя>`, и `scripts/link.sh` ставит их ссылками на клон. `task-run` и `task-fleet` помечены `metadata.internal` и ставятся только Claude Code. Скрипты скиллов проверяют запуск через `import.meta.main`: через ссылку прежнее сравнение `argv[1]` с путём модуля ложно, и скрипт молча выходил с нулём. Решение целиком в [skills-repo.md](./skills-repo.md).

## Откат на 2.9.0

2.9.0 работает со старым herdr 0.8.0 и живёт только плагином, поэтому откат идёт по тегу `v2.9.0`:

1. В каждой живой сессии задачи попроси остановиться (`stage stopped`), затем закрой её терминал `hc kill`: иначе сессии Herdr продолжат работу рядом с откатанными.
2. `git -C <клон> worktree add ~/.local/share/oberemokis-skills-2.9.0 v2.9.0`: отдельная копия, ссылки скиллов при этом ведут в основную папку клона и не меняются.
3. Убери ссылки `~/.claude/skills/task-run` и `~/.claude/skills/task-fleet`: иначе рядом с плагином сессии увидят новые версии тех же скиллов. Вернёт их следующий `link.sh`.
4. Оркестратор в старом herdr: `claude --plugin-dir ~/.local/share/oberemokis-skills-2.9.0`.
5. Каждую задачу продолжай прямым `/oberemokis-skills:task-run <ID>`: «Продолжение» перепишет `session` под старый herdr.

Теряется панель Review с её базой из `branch.<ветка>.base` (в gitone база задаётся командой) и привязка задач к пространствам Herdr.

## Как проверяем

- `node --test` по скриптам `task-run` и `task-fleet`, в том числе запуск через ссылку на папку, входит в `scripts/check.sh`.
- 2.7.0 и 3.0.0 вышли без живого прогона оркестратора. Для 3.0.0 вживую проверены по отдельности: `host.mjs` в терминале hc и вне его, `watch.mjs` на появлении и конце терминала, база ветки и `defaultPanel` в Review и Graph, `hc send` в оболочку без обёртки, закрытие пространства от `hc kill`, запуск с метками без смены пространства в окне в фоне.
- Первый боевой запуск 13 ноября 2026 опроверг подсчёт мест: под обёрткой на переднем плане терминала стоит оболочка, а не Claude. Исправлено в 3.0.1: Claude узнаётся по `status.app`, а с 15 ноября ещё и по процессу в группе переднего плана, потому что на вопросе о доверии папке `status` пустой.
- 15 ноября 2026 вживую проверен запуск через `launch.mjs`: метки и пространство, коды 4 и 5, диалог доверия, слэш-команда в аргументе запуска, `--replace`, закрытие пространства. Тогда же выяснилось, что `hc send` из терминала агента заворачивает текст в `<hc from>` и для оболочки, поэтому перезапуск идёт только через `launch.mjs --replace`. Не проверены `--resume`, стенд через `stand.mjs`, показ с Review и `/task-fleet` без аргументов.
