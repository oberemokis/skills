# task-run и work: запись решения

Ноябрь 2026. Скиллы заменяют личную очередь задач, которая вела до пяти задач по одной в одной сессии и была завязана на один проект. С версии 3.0.0 оркестратор `task-fleet` работал в Herdr (ядро hc и приложение) вместо старого herdr. 26 ноября 2026 он переименован в `work` и переехал в herdr TUI, раздел «Переезд на herdr TUI».

## Что решили

- Одна задача, одна сессия агента, один worktree, одно пространство herdr. Очереди нет: параллельность даёт `work`, маршрут одной задачи ведёт `task-run`.
- Ядро в этом репозитории, всё про проект у пользователя: `~/.local/state/task-run/<проект>/` с `project.json` (данные, схема), `rules.md` (правила прозой и глаголы трекера и код-хоста) и `tasks/<ID>.json` (состояние задачи). Ядро говорит глаголами («начал работу», «открыть MR») и не знает ни трекера, ни код-хоста.
- Проект узнаётся по нормализованному `origin`, корень это родитель общего `.git`. Основная папка и все worktree дают один проект.
- Первый вызов в проекте запускает опросник: он сам выясняет то, что видно в репозитории, трекере и код-хосте, спрашивает остальное и записывает после подтверждения. Снова он запускается только по `--setup` и когда данные или подключения сломаны. Токены через чат не проходят.
- Worktree лежат в `.worktrees/<ветка>` корня проекта. Создаёт их git с `--no-track`. База определяется до создания worktree.
- Этапы лежат справочниками внутри `task-run`: в списке скиллов два описания вместо девяти.
- `work` работает только в herdr TUI. Оркестратор узнаёт его по предкам процесса (`host.mjs` ищет `herdr server`), а не по переменным окружения: `HERDR_*` наследуются и туда, где панели herdr нет.
- Сессия задачи запускается в новом пространстве (`herdr workspace create --no-focus`) командой `herdr agent start` в оболочке его панели. Панель помечается токенами метаданных `work=1`, `task=<ID>`, `agent=<вид>`, `agent-session=<id>` и `project`. Закрытие задачи (`stop.mjs`: TERM процессу агента, затем KILL) и выход агента оставляют пространство с оболочкой. ID сессии Claude задаёт оркестратор (`--session-id`), поэтому перезапуск известен с первой секунды.
- Запуск сессии и старт стенда идут скриптами `work/scripts/launch.mjs` и `task-run/scripts/stand.mjs`, а не командой оболочки со встроенным кодом: хук lean-ctx встроенный код (`sh -c`) не пропускает. `launch.mjs` под `flock` считает места, ловит дубль задачи, ждёт агента в бюджете 90 секунд и отвечает кодом: 0 запущено, 4 мест нет, 5 задача уже идёт, 6 агент не поднялся (его процесс погашен).
- Надзор по токенам панелей, а не по родству: `watch.mjs` подписывается на события сокета herdr (`events.subscribe`), сравнивает снимки `api snapshot` и будит оркестратора только на перемене. Новый оркестратор видит сессии старого, закрытие его терминала сессии не убивает.
- Порядок ревью: агенты (M и L), затем дифф и показ в браузере одной остановкой перед коммитом. Замечание повторяет шаг целиком, поэтому в коммит уходит просмотренный дифф.
- Смотреть работу можно с начала, а не только на показе. У задачи с интерфейсом стенд и вкладка поднимаются перед первой правкой интерфейса и живут до одобрения показа. Вкладку ведёт расширение Claude in Chrome, поэтому пользователь видит и правки, и клики сценариев. Страницы для вкладки задача хранит в `context.pages`.
- Порт стенда один на машину. Занят чужой задачей на реализации: сессия работает без вкладки и не спрашивает, на показе вопрос остаётся.
- Файл задачи пишет только её сессия и только через `check-json.mjs --commit`. Внешние шаги идемпотентны: сверка с миром, намерение до действия, факт после. Правота: git и код-хост, затем трекер, файл последним.
- Флаг «в работе» снимается, пока сессия ждёт человека: иначе три ждущие сессии копят тройное время. Своих уведомлений нет: herdr сам показывает статус агента на вопросе и конце хода.
- До трёх живых сессий на машину, всех агентов вместе: панели, где herdr видит агента, с токеном `work=1` или внутри папок worktree, под `flock -w 20`. Сверх предела вопрос «отложить или ждать».
- Этапы всех задач были видны в панели «Задачи fleet» в сессии оркестратора, модуле хуков плагина (`hooks/fleet-panel`). С выходом из плагина панель удалена (последняя версия под тегом `v3.1.0`), и этап задачи виден только по строкам сессий в чате.
- Пропавшую сессию оркестратор сразу приостанавливает в трекере, а перезапускает только после вопроса: `launch.mjs --replace` с прежним ID сессии и `--resume`, а если файла сессии нет или выбран другой агент, новая сессия с промптом `task-run`, которая принимает передачу handoff прежней. После краха сервера herdr или перезагрузки `/work` без аргументов проходит по задачам и делает то же.
- Промпт без задачи идёт только на чтение: detached worktree, режим plan, запрет Edit и Write. Правки только через задачу.
- Красный пайплайн своей ветки: amend и `--force-with-lease` после backup-ветки, чтобы держать один коммит на ветку. В общие ветки force-push запрещён. Зелёным считается только пайплайн на голове MR, равной коммиту задачи; пайплайна нет, значит не зелёный.
- Проверка привязана к ревизии (взято из flow `work` другого проекта 17 ноября 2026). У каждого тестового случая результат с отпечатком диффа `scripts/fingerprint.mjs`, командой и статусом `pass`, `fail`, `not_run` или `not_applicable` с причиной; у прогона `verifiedDiff`, у показа `reviewedDiff` тем же скриптом. Доставка требует текущего `pass` у каждого случая: правка меняет отпечаток, и прежний результат становится историей.
- Этап start собирает контекст разведкой кода (`task-run/recon.md`): веер субагентов только на чтение по сторонам задачи (код, связи, тесты, история и чужие ветки, контракты), сверка их фактов сессией по ссылкам и с описанием задачи, карта `context.map` с SHA, где читали. По карте считаются уровень и швы, ревьюер правильности получает потребителей изменённого кода, а при продолжении карта сверяется с git и задетые части собираются заново.
- Допущения решения пишутся в `context.assumptions` с проверкой и ценой ошибки и проверяются до плана; непроверенные пользователь видит в плане.
- Внешний шаг засчитывается в `outbound` только после того, как результат перечитан в мире: ответ команды не говорит, куда и в каком виде легло действие.
- Комментарий в трекере перекрывает описание, но не решения пользователя и не записанные `decisions`.
- Ревью: граничные находки `correctness-reviewer` второй волной уходят `test-reviewer` на проверку покрытия; ревью без субагентов помечается как самопроверка.
- Визуальное ревью идёт само, если у задачи есть `context.pages` и дифф правит видимое на них: после ревью кода (на S в начале показа) `scripts/shots.mjs` снимает страницы стенда Playwright из проекта и обводит изменённые блоки красной рамкой, сессия смотрит снимки сама и пишет дефекты в `findings`. Снимки лежат в `~/Documents/task-run/<проект>/<ID>/round-<N>` и `show`, папка открывается в Finder, путь попадает в вопрос показа.

## Что отвергли и почему

| Вариант | Причина отказа |
| --- | --- |
| встроенные субагенты с изоляцией в worktree | живут внутри оркестратора, в Herdr их не видно и в их сессию не зайти |
| ветка от `origin/<база>` с upstream | первый `git push` уходит в базу |
| worktree до выбора базы | ветка от не той базы, а пересоздать worktree изнутри своей сессии нельзя |
| два оркестратора (общий `fleet` и тонкий `task-fleet`) | второй слой почти ничего не добавлял, а описание висит в контексте |
| этапы отдельными скиллами | девять описаний в каждой сессии ради того, что вызывается только из маршрута |
| адаптер проекта markdown-скиллом | висел бы в списке скиллов во всех проектах |
| папка проекта в репозитории | командный репозиторий не трогаем |
| знание YouTrack и GitLab справочниками в ядре | без второго проекта граница «инструмент вообще» и «инструмент этого проекта» угадана |
| список запрещённых идентификаторов в `scripts/check.sh` | сам опубликовал бы то, что прячем; проверка идёт по формам |
| счётчик мест в `fleet.json` | не знает о перезапусках и чужих оркестраторах, после падений врёт |
| автоматический перезапуск пропавшей сессии | Ctrl+C пользователя от падения не отличить, повтор доставки опасен |
| только режим plan для промпта без задачи | режим снимается, а основная папка бывает смонтирована в стенд |
| дифф и показ двумя остановками | правка после показа уходила в коммит непросмотренной |
| JSON-схема через ajv | зависимость ради подмножества, которого хватает своему валидатору |
| дифф и стенд только на показе | пользователь видел работу, когда переделка уже стоила круга исправлений |
| свой порт стенда на сессию | на других портах стенд проекта работает не целиком |
| вопрос про занятый порт на реализации | останавливает реализацию, а порт освобождается сам |
| вкладка командой `open` в браузере пользователя | видно правки, но не клики сценариев; остаётся запасным путём без расширения |
| fleet сразу для старого herdr и Herdr | два справочника команд и две живые проверки на каждую правку; откат на 2.x дешевле |
| снимки визуального ревью вкладкой Claude in Chrome | рамку на изменённом блоке не нарисовать, а вкладка бывает занята или недоступна |
| визуальное ревью по вопросу | задача с интерфейсом без снимков почти не бывает нужна, вопрос только останавливает |
| снимки в worktree или в папке проекта | в worktree они попадают в дифф, папку состояния пользователь не открывает сам |
| Playwright зависимостью скилла | у репозитория скиллов нет `package.json`, а в проекте с интерфейсом он обычно уже стоит |
| отдельный мод вне плагина | загружается только в той сессии, где его написали, оркестратор его не видит |

## Границы

- Проверено на одном проекте: граница ядра держится проверкой по формам, а не вторым проектом.
- Оркестратор только Claude, только один проект на запуск оркестратора. Сессии задач ведут агенты из таблицы `AGENTS` в `launch.mjs`; без `--work` задачу ведёт только Claude, потому что войти в worktree посреди сессии умеет только он.
- Нужен herdr 0.9.5 или новее: `agent start`, токены метаданных панели и подписка на события сокета.
- Показ задач с бэкендом на общем стенде не видит правок worktree, если стенд смонтирован из основной папки; такие задачи проверяются автотестами worktree.
- Плановой перепроверки папки проекта нет.
- Лок мест и порта стенда берётся через `flock`: в macOS его нет из коробки, нужен пакет из Homebrew.
- Вкладкой стенда за раз владеет одна задача: расширение Claude in Chrome общее на сессии, но порт держит одна.
- Стенд, переживший свою сессию, держит лок порта от имени закрытой задачи, и следующая задача на показе ждёт его. Так было и в старом herdr, исправление отложено.

## Выход из плагина

16 ноября 2026 репозиторий перестал быть плагином Claude Code: скиллы лежат плоско в `skills/<имя>`, и `scripts/link.sh` ставит их ссылками на клон. `task-run` и `task-fleet` помечены `metadata.internal` и ставятся только Claude Code. Скрипты скиллов проверяют запуск через `import.meta.main`: через ссылку прежнее сравнение `argv[1]` с путём модуля ложно, и скрипт молча выходил с нулём. Решение целиком в [skills-repo.md](./skills-repo.md).

## Агенты сессий

Обновление: Claude и OpenCode запускаются на управляющей машине. Для проекта с `execution.mode=ssh` исходники и все Git-операции остаются на удалённой машине, состояние и сессия на локальной. Выбрали SSH без монтирования: один путь не может служить одновременно удалённым worktree и cwd Herdr. После обрыва подтверждение команды может потеряться уже после записи; повторять её без сверки нельзя. Копию исходников на Mac отвергли: она не гарантирует показ того же диффа, который тестировался. [Действующий маршрут](../skills/task-run/remote.md).

17 ноября 2026 решили, что сессии задач ведут не только Claude, но и Codex и OpenCode. Оркестратор остаётся в Claude: надзор держится на фоновой команде, которая будит его при выходе, и на инструменте вопросов. Работа идёт четырьмя ветками, каждая с живой проверкой своего этапа:

1. Общий детектор агентов и подготовка, поведение пока только Claude: таблица `AGENTS` в `launch.mjs`, агент ищется в дереве процессов терминала от его корня, метка запуска `fleet-launch`, бюджет времени, код 6 гасит агента, `stop.mjs`, поля `agentKind` и `agentSession` в `task@1`, поле `agent` в `project.json`, передача handoff при стопе и остановке.
2. Codex: узкая песочница (gitdir worktree, objects, refs, logs, packed-refs, папка проекта task-run, `/tmp`, сеть; `.git/hooks` и `.git/config` закрыты; lean-ctx выключен), ID сессии пишет сама сессия из `CODEX_THREAD_ID`, вопросы через `request_user_input`, `task-run` ставится в `~/.agents/skills` с `agents/openai.yaml`.
3. OpenCode с `--standalone`: свой сервер на сессию вместо общего.
4. Вкладка стенда через MCP `browse` у всех агентов и мод reviewer, который шлёт замечания любому агенту.

Агент задачи берётся из флага `--agent`, затем из `project.json`, затем `claude`. Предел три сессии общий. Перезапуск другим агентом идёт новой сессией по файлу задачи, git и передаче handoff. Файл задачи главнее передачи: из неё берутся только тупики и следующий шаг внутри этапа.

Сливать любую из четырёх веток можно только при пустом fleet: скиллы стоят ссылками на клон, и живые сессии с оркестраторами подхватывают новый код посреди задачи, держа старый текст скилла в контексте. Перед слиянием `ps -A -o args= | grep watch.mjs` пуст, терминалов с меткой `task-fleet=1` нет.

| Вариант | Причина отказа |
| --- | --- |
| схема `task@2` с переименованием `session.agent` в `terminal` | живые сессии падают на следующей записи, а поле меняет смысл между версиями |
| поиск ID сессии Codex в `~/.codex/state_5.sqlite` по папке и времени | ловит чужие треды и подагентов, зависит от внутренней схемы Codex, упирается в вопрос доверия |
| общий сервис OpenCode | TERM в TUI не останавливает ход, а сессия fleet может стать хозяином сервиса для всей машины |
| запись Codex во весь `<repo>/.git` | хук из `.git/hooks` выполнится у пользователя вне песочницы |
| агент по группе переднего плана | после Ctrl+Z агент уходит из группы, и живая сессия выглядит пропавшей |
| код совместимости меток и вывода надзора | остаётся в скрипте навсегда ради трёх сессий в момент слияния |
| передача handoff после закрытия задачи | передавать нечего, а TERM от оркестратора оставляет пустую заготовку |
| одна ветка на всех агентов | живая проверка OpenCode ждёт починки конфига, вкладка проверяется только на показе |
| агент `plan` OpenCode для сессий только на чтение | флагом у TUI не выбирается, shell не запрещает, перекрывается глобальным allow |
| оркестратор в Codex и OpenCode | пришлось бы переписать надзор и вопросы, выигрыш мал |
| отдельный CLI `fleet` вместо скриптов скилла | пользователь решил оставить механику в скилле |
| разведка силами самой сессии | контекст задачи забивается логами поиска до реализации, а сжатие съедает подробности |
| объём разведки по уровню задачи | уровень считается по карте, до разведки его нет; маленькая задача и так даёт короткую разведку |
| факты субагентов без сверки | субагент ошибается тем же уверенным тоном, что и прав; решение держится только на прочитанной строке |
| из чужого flow `work`: коммит, пуш и PR без подтверждения | у нас коммит намеренно идёт после одобренного показа |
| из чужого flow `work`: отчёты о приёмке, брифы и передачи в `docs/` репозитория | состояние задачи живёт вне репозитория, командный код не трогаем |
| из чужого flow `work`: память ревьюеров в репозитории | у пользователя уже две памяти, третья их размоет |

## Переезд на herdr TUI

26 ноября 2026 оркестратор `task-fleet` переименован в `work` (`/work`, флаг `--work` у `task-run`, поле `work` в `task@1`, токен панели `work=1`) и работает в herdr TUI 0.9.5 вместо ядра hc и приложения herdr-app. Обоих больше нет ни в скиллах, ни в скриптах.

- Агента в панели видит сам herdr (`pane.agent`): он есть на вопросе о доверии и после Ctrl+Z и пропадает с выходом агента. Дерево процессов от оболочки панели нужно только `stop.mjs` и признаку `stopped` в надзоре.
- `herdr agent start` сам набирает команду агента в оболочке панели и ждёт готовности. Обёртка `"$0" "$@"; exec "$SHELL" -l` не нужна: панель и так остаётся оболочкой, и перезапуск после выхода агента идёт в ту же панель.
- Вопрос о доверии `agent start` отдаёт ошибкой `agent_not_ready`, агент при этом жив; `launch.mjs` читает экран и отвечает `trust: true`. Агент, который сразу вышел, даёт `timeout` и пустую панель, это код 6 с `reason: exited`.
- Агента, остановленного Ctrl+Z, в fish не берут ни TERM с CONT, ни HUP: оболочка снова останавливает задачу. `stop.mjs` ждёт и добивает KILL.
- Пространство создаётся без фокуса, поэтому окно пользователя возвращать не нужно. Дерева пространств с родителем в herdr нет.
- Показ диффа сессией убран целиком вместе с записью базы ветки в `git config`, которая была нужна только ему. Вопрос показа несёт diffstat и новые файлы.
- Совместимости со старыми файлами задач (поле `fleet`) и метками нет: на момент переезда живых задач под оркестратором не было.

| Вариант | Причина отказа |
| --- | --- |
| имя `task-work` | пользователь выбрал короткое `work` |
| хост на выбор: herdr TUI, hc или herdr-app | два справочника команд и живые проверки на каждую правку |
| надзор опросом `api snapshot` по таймеру | будит позже события и гоняет снимок впустую; подписка на сокет даёт перемену сразу |
| живость по дереву процессов, как под hc | herdr уже знает агента панели, в том числе на вопросе о доверии и после Ctrl+Z |

## Рамки ревью и конец задачи

26 ноября 2026, по разбору 65 задач одного проекта.

- Ревью и аудит идут только по диффу задачи и её коммитам. Находка остаётся, если стоит на изменённой строке или на потребителе, которого сломало изменение. Остальное отбрасывается без упоминания. Так сказано в этапе review, в скилле `review` и в обоих ревьюерах.
- Точка отсчёта задачи считается в `fingerprint.mjs --point`: merge-base с `origin/<база>` и с локальной `<база>`, берётся более новая. Задача на стопке поверх ветки, которой нет в origin (PROJ-2 поверх локальной ветки PROJ-1), раньше либо падала на `merge-base`, либо тащила в дифф нижнюю задачу. Той же точкой пользуются отпечаток, verify, show и ревью.
- Доставка `local`: коммит остаётся в ветке задачи без push и MR, закрытие не ждёт слияния и не трогает трекер. Раньше это правило жило в памяти Claude, и задачи закрывались по-разному: доставка `skipped` при готовом коммите, закрытие то `done`, то `skipped`.

| Вариант | Причина отказа |
| --- | --- |
| находки вне диффа в текст закрытия | пользователь выбрал не упоминать их вовсе |
| убрать встроенный `code-review` | пользователь оставил его, его находки проходят тот же фильтр рамок |
| аудит по всему затронутому пакету | выходил за рамки задачи |
| точка только от `origin/<база>` | ломает задачи на стопке поверх локальной ветки |

## Откат на 2.9.0

2.9.0 работает со старым herdr 0.8.0 и живёт только плагином, поэтому откат идёт по тегу `v2.9.0`:

1. В каждой живой сессии задачи попроси остановиться (`stage stopped`), затем закрой её терминал `hc kill`: иначе сессии Herdr продолжат работу рядом с откатанными.
2. `git -C <клон> worktree add ~/.local/share/oberemokis-skills-2.9.0 v2.9.0`: отдельная копия, ссылки скиллов при этом ведут в основную папку клона и не меняются.
3. Убери ссылки `~/.claude/skills/task-run` и `~/.claude/skills/task-fleet`: иначе рядом с плагином сессии увидят новые версии тех же скиллов. Вернёт их следующий `link.sh`.
4. Оркестратор в старом herdr: `claude --plugin-dir ~/.local/share/oberemokis-skills-2.9.0`.
5. Каждую задачу продолжай прямым `/oberemokis-skills:task-run <ID>`: «Продолжение» перепишет `session` под старый herdr.

Теряется привязка задач к пространствам herdr.
