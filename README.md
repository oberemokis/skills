# skills

Личные agent skills для Claude Code. [`skills/core`](./skills/core/SKILL.md) подключается сам и несёт базовую настройку: правила текста, маршрутизацию к скиллам стека, критерии завершения. Дорогие этапы вызываются руками: `/oberemokis-skills:grill` перед работой, `/oberemokis-skills:humanizer` для вычитки текста.

## Установка

```
/plugin marketplace add oberemokis/skills
/plugin install oberemokis-skills@oberemokis
```

Обновление после изменений:

```
/plugin marketplace update oberemokis
```

## Структура

```
skills/
├── core/          базовая настройка: текст, маршрутизация, завершение
├── grill/         допрос, вызывается руками
├── architecture/  слои монорепы, границы пакетов, куда положить код
├── test/          методологии тестирования: хаб и семь скиллов
├── stack/         правила и API по технологиям, одна папка на технологию
├── git/           работа с историей: commit
└── misc/          humanizer: вычитка текста, вызывается руками
```

Незаполненные скиллы лежат в `drafts/` рядом со `skills/`, сейчас там `design`. Автопоиск заглядывает только в `skills/`, поэтому заготовка из `drafts/` в контекст не попадает. Исключить её из манифеста, оставив в `skills/`, не выйдет: массив в манифесте автопоиск дополняет, а не отменяет.

В `test` лежит хаб с общими правилами и семь скиллов под ним: `tdd`, `unit-tests`, `integration-tests`, `e2e-tests`, `test-review`, `coverage`, `bug-hunting`. Там методологии, а не инструменты: как писать тесты на конкретном раннере, смотри в `stack`.
