# skills

Личные agent skills для Claude Code.

## Установка как плагин

```
/plugin marketplace add oberemokis/skills
/plugin install skills@oberemokis
```

Обновление после изменений в репозитории:

```
/plugin marketplace update oberemokis
```

## Как это работает

Точка входа одна: [`skills/core`](./skills/core/SKILL.md). Любая задача проходит через неё, и уже она решает, что грузить дальше.

```
core          грузит humanizer, передаёт в grill, маршрутизирует,
              задаёт критерии завершения
 ├─ humanizer      правила текста для человека, до первого ответа
 └─ grill          допрос по дереву решений, факты добывают агенты
     └─ test, stack, design, ...   методологии и правила
```

`humanizer` подтягивается нулевым шагом, до первого ответа. Причина в том, что его правила работают только до письма: загруженные потом, они превращаются в переписывание уже сказанного. На код, комментарии и инструкции агентам они не распространяются.

Каждый подтянутый скилл называется вслух, с причиной:

```
Скиллы: humanizer (текст для человека), grill (любая задача)
Скиллы: + test/integration-tests (шов на странице с реальным стором)
```

Причина нужна больше имени: по ней видно неверный выбор, пока он ещё ничего не стоит. Если не подтянуто ничего, это тоже говорится, иначе молчание не отличить от несработавшей маршрутизации.

Grill не делит задачи на категории. Он держит задачу как дерево решений и задаёт раундами то, что можно спросить сейчас, не угадывая ответов, которых ещё не слышал. Такой раунд называется фронтиром. Ответы перекраивают дерево, фронтир выталкивается наружу, и так до пустого фронтира.

Тяжёлые стадии включаются условием, а не ярлыком сложности:

| Стадия | Условие |
| --- | --- |
| разведка агентами | фронтиру нужен факт из окружения |
| варианты | подход неизвестен или решение необратимо |
| швы | набрался хотя бы один случай |
| план | работа затрагивает больше одного файла |
| опровержение | меняется чужой контракт, откат дорогой, или задача пересекает слои |

Количество агентов не задаётся числом, оно выводится из единицы деления: по одному агенту на факт при разведке, от трёх при поиске вариантов, по одному на линзу при опровержении. Перед каждым запуском печатается таблица с заданиями, и она же место, где вы вмешиваетесь.

На выходе grill даёт границы, список случаев и согласованные швы. Шов это точка, где поведение наблюдаемо снаружи, и он же определяет форму теста: функция без зависимостей даёт unit, модуль со своими реальными зависимостями даёт integration, поведение, видимое только в запущенном приложении, даёт e2e. Тип теста не выбирается отдельно, он падает из шва, а число тестов равно числу случаев.

Подробности в [`skills/grill`](./skills/grill/SKILL.md).

## Структура

```
skills/
├── core/        точка входа: grill, маршрутизация, завершение
├── grill/       дерево решений, фронтир, агенты
├── test/        методологии тестирования (хаб + семь скиллов)
├── stack/       правила и API по технологиям, одна папка на технологию
├── design/      компоновка, типографика, визуальные решения
├── git/         работа с историей: commit
└── misc/        humanizer: правила текста для человека
```

В `test` лежит хаб с общими правилами и семь скиллов под ним: `tdd`, `unit-tests`, `integration-tests`, `e2e-tests`, `test-review`, `coverage`, `bug-hunting`. Там методологии, а не инструменты: как писать тесты на конкретном раннере, смотри в `stack`.

## Добавление скилла

1. Создать `skills/<путь>/<имя>/SKILL.md`. Имя в нижнем регистре, слова через дефис.
2. Заполнить фронтматтер. `description` это единственное, что Claude видит всегда, поэтому в нём должны быть триггеры: слова, типы задач, имена файлов. Без внятного описания скилл не подключится.
3. Первой строкой после заголовка оставить ссылку на core, чтобы скилл не читался в обход точки входа.
4. **Запустить `./scripts/sync-manifest.sh`.**

Четвёртый шаг обязателен. Автодискавери Claude Code находит `SKILL.md` только на один уровень вложенности от `skills/`, поэтому всё, что лежит глубже (`skills/<категория>/<имя>`), обязано быть перечислено в `.claude-plugin/plugin.json` явно. Забыли перечислить, скилл просто не загрузится, и никакой ошибки при этом не будет. Скрипт пересобирает список из файловой системы и заодно проверяет битые пути и повторяющиеся `name`.

## Версии и публикация

Версия живёт в `package.json`, поднимается через changesets и копируется в манифест плагина скриптом.

```bash
pnpm changeset          # описать правку, выбрать patch, minor или major
pnpm version            # поднять версию, собрать CHANGELOG, обновить манифест
```

`pnpm version` делает три вещи: `changeset version` поднимает версию и дописывает `CHANGELOG.md`, `sync-plugin-version.mjs` копирует её в `.claude-plugin/plugin.json`, а `sync-manifest.sh` пересобирает список скиллов.

`pnpm check` ничего не меняет и падает, если версия в манифесте разошлась с `package.json` или список скиллов устарел. Годится для хука или CI.

Дальше закоммитить и запушить в `main`, затем `/plugin marketplace update oberemokis`.
